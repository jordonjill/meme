Keep: what an agent would want to know beyond one project: services and set-ups several projects use (where a model gateway or a package registry is, how to reach it, never a secret), how the user's company or team works (how changes are reviewed and released, where documents go), work the user is doing over many sessions and what was decided about it, and what is worth keeping from a session that is in no project.
Leave out: what holds in one project only, which is a fact about that project; how agents should work with the user, which is a rule; who the user is, which is about the user; what holds only today; secrets.
Write it as a fact that stands on its own: name what it is about, since it is read in every project.
Good: "The team's model gateway is at https://llm.example.com/v1 and takes an OpenAI-style key; it serves qwen-plus."
Not this: "Looked up the gateway address today." (an event, not a fact)
