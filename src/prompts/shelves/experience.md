Keep: what was learned from how something turned out: a failure and what fixed it, a way that worked where others had not, the user correcting the agent. It rests on the outcome: a failing tool output and the fix that followed, or the user's words.
Leave out: what was tried and not settled; steps that went as expected; what any agent knows already, unless this session showed it to be a trap here.
Write what to do, with the situation it applies in as "when", and what goes wrong otherwise as "why".
Good: "Start the database before running the tests", when "running the project's tests", why "they fail with ECONNREFUSED otherwise".
Not this: "Ran the tests, fixed the bug, all tests pass now." (progress, no lesson)
