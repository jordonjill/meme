Keep: what was learned from a problem met in this session and how it was solved: an error and its fix, a bug the user reported and what caused it, a way that worked where others had not, the user correcting the agent. Keep it when an agent meeting the same situation would want to know it, even if the knowledge itself is general: here it cost time.
Leave out: what was tried and not settled; steps that went as expected; general advice that did not come up as a problem in this session.
Write what to do, with the situation it applies in as "when", and what goes wrong otherwise as "why".
Good: "Start the database before running the tests", when "running the project's tests", why "they fail with ECONNREFUSED otherwise".
Not this: "Ran the tests, fixed the bug, all tests pass now." (progress, no lesson)
