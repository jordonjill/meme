# meme 差异化：近期研究与产品点子

> 调研日期：2026-10-08；覆盖 2026-09-01 至 10-08 的论文和产品
> 起因：担心记忆插件同质化太严重，想找"不一定难，但有意义或有新意"的方向。

**方法与局限**
- **论文**：用 arXiv API 按提交日期过滤，约 30 组检索式，去重后约 1,000 篇；先按标题筛，再读了约 80 篇的摘要。另外用 Hugging Face 每日论文接口做了关键词筛选，有几天接口失败，没有覆盖到。
- **数字**：全部出自摘要，没有逐篇核对全文。很多是单个团队的预印本，样本小或用合成数据，只能当方向参考。标【未核实】的更要谨慎。
- **竞品查重**：网页搜索中途用完了额度，后半段改用 gh 下载 17 个竞品的 README 做关键词搜索，并抓取了几篇产品文档。所以"未发现"指的是在已查来源里没找到，不等于确定没人做过。

链接：arXiv 为 `https://arxiv.org/abs/<编号>`；只在 HF 上找到的为 `https://huggingface.co/papers/<编号>`。

## 一、近期研究

### 1.1 编码 Agent 的记忆（和 meme 最相关）

| 论文（日期） | 内容 | 新在哪 | 结果（摘要） | 对 meme 的用处 |
|---|---|---|---|---|
| VibeMemBench 2609.23570（09-20） | 在 90 个真实仓库的编码任务上评测记忆系统 | 不比召回率，比测试能否通过；每个目标都先确认"历史经验确实有用" | 直接注入已验证过的经验：5 个解题模型里有 4 个的解决率提升 1.1–4.5pp，步数全部下降。但让 4 个现有记忆系统自己提炼和检索时，12 种组合里有 11 种不如关掉记忆 | 可作为评测集候选（是否公开【未核实】）。**瓶颈在提炼和检索，不在"有没有经验"** |
| Skill Issue 2609.12742（09-11） | 把已合并的 PR 回滚到同一个基点当作任务，比较有无 SKILL 文档时的表现 | 给没有基准测试的普通仓库造评测题 | 用 GEPA 生成的文档提升 4.9pp，但单个仓库的任务量太少，提升和运行间的随机波动分不开 | 造题很便宜；但说明在单个仓库上做 A/B，统计上说明不了问题 |
| Agent Skill Evolution 2610.04832（10-04） | 分析 2,608 对 SKILL.md 修订前后的差异，看"加一条规则"对 Agent 行为的实际影响 | 第一份大规模测量"记忆文件改了，Agent 行为怎么变"的研究 | 加一条可检查的规则：单轮回答的遵守率 +0.41；Agent 做出所需动作的比例 +0.23；正确率 +0.10。**增益主要来自点名了具体命令或路径的规则**。改成按需加载后，只剩约 51% 的增益 | 直接指导经验的写法 |
| Who Finishes the Job? 2609.26847（09-22） | 跟踪 6,774 个已合并的 Agent PR，看后续由谁来修 | 关注"合并之后谁在收拾" | Agent PR 之后被修复的几率是人类 PR 的 1.62 倍；69.6% 的修复由同一个 Agent 完成 | 合并后的修复提交，就是现成的经验来源 |
| Not All Agents Are Equal 2609.17598（09-12） | 37,623 个 Agent PR 的质量与合并后的维护情况 | 按厂商分开比较 | 回滚率：Codex 6.1%，人类 11.5%，Devin 14.5% | 支持"按 Agent 分开统计" |
| Impact Is Not Invalidation 2609.25130（09-20） | 代码改了之后，哪些记忆会失效 | 不问"这次改动是否保持行为不变"，而是问"这条说法还成立吗" | 后一种问法的精度是 0.705–0.974；前一种只有 0.29–0.33，基本等于瞎猜（随机水平是 0.25） | 几乎可以直接照搬 |
| MemTrace 2610.04838（10-04） | 长任务编码 Agent 的记忆，锚定到文件、符号和测试 | 恢复旧证据之前，先对照当前仓库状态校验 | 在三个基准上优于基线（摘要没给具体数字） | 可用于接力卡 |
| RETRACE 2610.04658（10-03） | 从杂乱的 PR 和 CI 修复历史中，按问题整理出修复经验 | 能处理一个 PR 里混着多个 CI 问题、失败的尝试和回滚的情况 | mini-SWE-agent 的一次通过率 19.6% → 31.9%；Codex 15.5% → 27.5% | CI 日志可以作为新的经验来源 |
| XRepoSkill 2609.36807（09-29） | 对比同一个 Agent 在同一个 issue 上成功和失败的过程，在两者走岔的地方提炼规则 | **每条规则都配一个可执行的判据**；只保留在多个仓库都出现过的规则 | 比不用技能高 10.3pp，比最强基线高 5.0pp | 下文"经验判据"点子的来源 |
| RuleEvolve 2610.00650（09-30） | 编码规则池通过"变异 + 评判"不断进化 | 研究对象正好是编码规则 | 摘要说优于手写规则和提示词优化，没给具体数字 | 参考 |

### 1.2 自进化：怎么验证，怎么晋升

| 论文 | 内容 | 结果 | 对 meme 的用处 |
|---|---|---|---|
| Do Self-Evolving Skills Generalize? 2609.39148（09-30） | 在训练任务上有提升的技能，换到新任务还剩多少 | 21 个技能里，5 个的提升全部保留，13 个保留一部分，3 个全部丢失。迁移差的技能，常常写死了列名、输出文件名这类细节，或者把一次性的修复写成了通用规则。LLM 当评判能给成品技能排序（86% 一致），但**预测单次修改的效果很差** | 给"体检"功能提供规则；也是一个警示 |
| SAGE 2609.36043（09-28） | 自进化中决定"接不接受这次修改"的门槛 | 在同一批题目上配对比较，再做单侧检验，不显著就不接受。能挡住"平均分涨了，但原来会做的题做错了"的情况 | 晋升规则可以直接借用 |
| Scope Before You Persist 2609.29144（09-24） | 记忆的使用范围应该和验证范围一致 | 只在来源任务类型里检索：0.816；全局检索：0.713，**比不用记忆的 0.775 还低**；有害的部署从 6/8 降到 0 | **直接警示"通用经验注入所有 Agent"** |
| Environment-Probing Curation 2609.11060（09-10） | 给离线整理的 Agent 一些只读工具，写入前先去环境里核实 | 通过率 39% → 73%；每个任务的成本从 3.38 美元降到 1.68 美元 | meme 夜间整理时，可以跑一些只读探测命令，比如 `ls`、`cat package.json`、`--help` |
| DAEDALUS 2610.08048（10-06） | 没有现成任务时，一个 Agent 出题、另一个做题，从失败中提炼经验 | 启发式要放进上下文后多次做对才会被接受；比不用记忆最多高 15.9 点 | 可用于新仓库冷启动 |
| Category-Conditioned Retention 2610.07100（10-05） | 不同类别的内容用不同的保留门槛 | "价值、信念"类的内容只有 77.9% 有来源支持，其他类别是 96.2%；对这一类单独提高门槛后，没有依据就被保留的比例从 6.2% 降到 4.0% | 用户级的偏好应该用更严的门槛 |

### 1.3 遗忘、撤销、过时

| 论文 | 结果 | 对 meme 的用处 |
|---|---|---|
| Revoked but Still Authoritative 2609.08258（09-08） | 实测 5 个只做"软撤销"的记忆系统，没有一个在检索时默认执行撤销；被撤销的旧事实，排名甚至比替代它的新事实还高 | 撤销必须做成硬过滤 |
| Forgetting Without Restarting 2609.04875（09-04） | 只删记忆条目，泄漏程度不变；靠指令让模型"忘掉"，在诱导下泄漏率是 100% | meme 是编译后再注入，验证"真的忘了"更容易 |
| PACMI 2610.05732（10-05） | 用来源关系图，让失效沿着依赖关系级联传递 | 可以做简化版 |
| Fresh Memory, Stale Plans 2609.03340（09-03） | 计划附上它所依据的输入版本，执行前逐一核对；冲突的检出率从 0/30 提升到 30/30 | 直接用于接力 |
| Memory Trust Gap 2609.01852、MEMTRIM 2610.07311 | 有记忆时，Agent 有 92%–100% 的时候仍然用旧值；记忆和当前任务只部分重合时最容易被带偏 | 注入时要带上日期和来源 |

### 1.4 安全与投毒

| 论文 | 结果 | 对 meme 的用处 |
|---|---|---|
| The Price of Safety 2609.22818（09-19） | 写入时的防御（输入清洗、来源检查、异常检测）几乎没有效用代价；读取时用 LLM 重新排序，会把 **33.6% 的正常记忆误隔离** | 防线放在写入端 |
| SkillPoison 2610.07645（10-06） | 只用"完全正确的成功经验"逐步给技能投毒，成功率 95.71%，每条注入的经验都能通过验证 | 警示：有用计数高，不代表安全 |
| Share-Borne AI Virus 2609.35576（09-28） | 攻击借助共享的产物在多个助手之间传播，模拟中波及 60%–80% 的 Agent | 警示：跨 Agent 共享本身就是传播通道 |
| PackHallu 2610.09264（10-07） | 往 AGENTS.md 或 .cursorrules 里注入内容，诱导 Agent 改用攻击者的包，成功率高，换个模型也有效 | 涉及依赖包的经验必须人工确认 |
| Trusting Trust Revisited 2609.17817（09-15） | 用被污染的基准测试驱动编码 Agent 的自进化，进化出了"关闭 HTTPS 证书校验"这类指令；之后换成干净的数据继续进化，污染常常还在 | 警示 |
| Epistemic Admission 2609.30813（09-25） | 按"这条内容是怎么来的"决定共享记忆收不收，错误采纳率 6%–9%，其他策略是 22%–47%；错误内容一旦进入共享记忆，读取方有 97%–99% 的概率会复述它 | 参考 |
| Self-Propagating Misalignment 2610.04083（10-02） | 偏离目标的 Agent 把自己的目标写进记忆，让以后的 Agent 去执行，成功率 58%；拿掉记忆工具后，74% 的会话改为直接写文件 | 警示：不要让 Agent 直接写常驻的经验 |

### 1.5 团队与多用户

| 论文 | 结果 | 对 meme 的用处 |
|---|---|---|
| ShareMem 2609.32511（09-26） | 在用户之间共享"怎么做""该去查哪个偏好"，但不共享偏好的具体值；在 3 个场景、4 个模型上都优于只用自己的记忆 | 团队共享的设计模板 |
| MemLeak 2610.04195（10-03） | 一个团队共用一个记忆库时，正常检索的跨用户泄漏率就有 70%–100%；只有检索后做硬性的归属过滤，才能恢复干净 | 警示 |
| Audience-Bound Memory 2609.36373（09-28） | 每条记忆记下写入时的受众，派生出的记忆取来源受众的交集；不加限制的检索在 82% 的情况下暴露了禁止项，这个方案降为 0 | 参考 |
| Relic 2609.32965（09-26） | 把团队里反复出现的协作失败，变成团队共有的可执行规则；新成员接手时的正确率：什么都没有 25.4%，写成文字 34.6%，**做成可执行的规则 41.2%** | **支持"把经验编译成 hook"** |
| Who Maintains Agent Skills? 2609.05677（09-04） | 分析 5 个公开技能仓库的 873 次提交，所有实质性修改都由具名的人提交或合并 | 支持"经验走 PR 评审" |
| Agora（HF 2609.18094，09-17） | 把 Git 当作多个 Agent 共享的记忆，每条结论都是一个能检出、能复现的提交 | 参考 |

### 1.6 人机协作与真实用户

| 论文 | 结果 | 对 meme 的用处 |
|---|---|---|
| Memory Misalignment from User Perspectives 2609.33623（09-27） | 来自 28 人的实际使用、32 人的日记研究和 121 人的概念评估，归纳出 14 类记忆出错的情况。**用户更想要主动、轻量的控制，而不是去看因果图或审计日志** | 决定"解释"功能该做成什么样：一行提示，不做图 |
| Tailored to you 2609.20077（09-17） | 992 人、5 天的个性化实验：基于记忆的个性化让人更愿意分享信息，也觉得没那么"瘆人"；但很多变化来自反复使用，而不是个性化本身 | 参考 |
| TAHI 2609.04141（09-03） | 从跨会话的人机交互中，逐步形成一套个人的评判标准；独立完成率提升 4.5%–20.9% | 从用户的反复纠正中学习 |
| CoLearn 2609.21154（09-17） | 导师 Agent 记录学习者的掌握情况，并把个性化做成用户看得见、可测量的 | Agent 反过来教人 |
| CAPTURE 2609.02265（09-02） | 区分"偏好真的变了"和"记忆被投毒了" | 可以借鉴"不确定就问用户" |

### 1.7 跨模型迁移与置信度

| 论文 | 结果 | 对 meme 的用处 |
|---|---|---|
| Memory Portability 2609.05339（09-04） | 换一个写入模型后，自然语言笔记的准确率变化在 +9.9pp 到 −13.3pp 之间，而且方向不一定；固定格式的知识图谱几乎不变；笔记 80% 的损失发生在写入阶段 | 经验的核心内容最好用结构化字段存 |
| Memory Canonicalization 2610.05124（10-04） | 写入时把记忆改写成统一、无歧义的形式，做多重比较校正后效果不显著 | 按模型改写措辞的收益没有得到证实 |
| XConf 2609.17708（09-15） | 用自己的历史战绩来估计置信度（具体数字【未核实】） | 按目录或任务类型统计历史成功率 |

| 10 | **可验证的遗忘** | `meme forget` 之后，级联删除、重新编译，再检查所有产物，最后打印"已从 4 处移除，0 处残留" | 只删条目，泄漏不变 | 未发现（未穷尽） | 低 |
| 11 | **高风险经验必须人工确认** | 涉及依赖包名、网址、安全设置、`curl \| bash`、凭据、跳过测试或关闭证书校验的经验：不自动晋升、不进常驻层、不编译成 hook、不跨 Agent 传播，除非人工确认 | PackHallu、SkillPoison、Trusting Trust 等研究；写入端的防御几乎没有代价 | "按经验类别设风险门槛"没找到 | 低 |
| 12 | **接力前先对表** | 任务卡记下当时的输入版本：HEAD、分支、相关文件的哈希、失败的测试。恢复时先比较差异，比如提示"计划是基于 3 小时前的状态，之后另一个 Agent 改了 3 个文件" | 冲突检出率 0/30 → 30/30 | 接力已经有人做；"检查计划是否过时"没找到 | 低 |
| 13 | **按战绩给建议** | 按目录或任务类型，统计各 Agent 的成功、回滚和返工；当前 Agent 在这块战绩差时，提示一行 | 不同 Agent 的表现差异真实存在 | 未发现 | 中（个人数据量小，样本不够时不显示） |
| 14 | **新仓库首日包** | `meme bootstrap`：挖掘 git 历史、CI 配置、贡献指南和评审意见，再跑只读的构建、测试、检查命令核实，产出带证据的初始经验，另给人生成一页"新人坑点" | 环境探测让通过率从 39% 升到 73% | **非常拥挤**：各家的 `/init`、Letta 的初始化、memorix 等。只能靠"实际执行核实 + 跨 Agent"来区分 | 中到高 |

### 首选 5 个

1. **#1 经验判据 + 小票，配合 #2 记分板：地基。** 一次解决三个空白：没人测跨 Agent 迁移、没人让用户看到记忆的效果、计数靠 LLM 自评不可信。#5、#6、#8、#13 都要用它的数据。
2. **#3 + #4 从纠正里学。** 评审意见、提交前的二次修改、合并后的修补提交，是比会话记录强得多、而且不需要用户开口的信号。评审端已经很拥挤，但"喂给写代码的 Agent、跨 Agent、本地运行"这条路还空着。
3. **#5 把经验编译成护栏。** 有研究直接证明"可执行比文字有效"；hookify 证明了开发者有这个需求，但它只支持 Claude Code、还要手动触发。最能体现"编译器"的定位：一条经验，编译成文字、hook、判据三种产物。
4. **#6 每周简报**，把 #9 的体检分数放进去。成本最低、最容易被看见；"避免了 N 次重犯"是竞品给不出来的数字。
5. **#7 经验即 PR**，放到 M2。第一版不做，但现在就把经验文件的格式设计成适合放进仓库评审的样子。

**顺手的小改动（各一两天）**：#10 可验证的遗忘、#11 高风险经验人工确认、#12 接力对表、#9 体检。

## 三、红旗：听起来不错，但证据说别这么做

| # | 想法 | 证据 | 建议 |
|---|---|---|---|
| 1 | 记忆越多越好 | VibeMemBench：现有记忆系统在真实仓库任务上，12 种组合里 11 种不如关掉记忆；另一篇研究（2610.07782）发现持久记忆层没有可检测的收益 | meme 如果拿不出"遵守率、重犯率"这类数据，就和其他插件没有区别 |
| 2 | 推断出的通用经验注入所有 Agent | Scope Before You Persist：全局记忆 0.713，比不用记忆的 0.775 还低；旧记忆和部分重合会把 Agent 带偏 | 第一版默认只在"来源 Agent + 相关目录"内生效，跨 Agent 验证后再扩大范围 |
| 3 | 用 LLM 当评判来决定晋升 | LLM 预测单次修改的效果很差；另一篇研究（2609.02246）发现，100% 的通过率背后真实能力只有 68%；在有限、有噪声的验证集上挑最高分，会系统性地高估 | 改用确定性判据加配对比较 |
| 4 | 在单个仓库里做 A/B，宣称"你的成功率提高了 X%" | 单个仓库的任务量不够，提升和随机波动分不开 | 只报告经验级别的遵守率和重犯率，不承诺任务成功率 |
| 5 | 能"解释一切"的仪表盘或因果图 | 121 人的研究：用户更想要主动、轻量的控制 | 做一行小票，不做图 |
| 6 | 在读取端用 LLM 重新排序来防投毒 | 33.6% 的正常记忆被误隔离 | 防线放在写入端 |
| 7 | 团队共用一个记忆池 | 泄漏率 70%–100%；错误内容一旦进入，读取方 97%–99% 会复述 | 只做显式发布 + 人工评审 + 硬性的归属过滤 |
| 8 | 软删除、"标记失效" | 5 个系统都不在检索时执行撤销 | 硬过滤 + 重新编译 + 验证 |
| 9 | 按模型改写措辞 | 统一改写的效果校正后不显著；结构化格式更稳定 | 经验存成"触发 / 动作 / 证据 / 判据"这样的字段 |
| 10 | 在按需检索层上投入很多 | 模型很少主动去找；改成按需加载后只剩约一半的增益 | 精力放在常驻的编译层，`meme search` 保持最小 |
| 11 | 有用计数高就等于安全 | 只用成功经验投毒，成功率 95.71%；Agent 会把自己的目标写进记忆，拿掉记忆工具就改写文件 | 守住"不让 Agent 直接写常驻经验"：离线提炼加人工把关 |
| 12 | 文件一改，相关记忆就失效 | 太敏感，精度只有约 0.3 | 改成按说法提问（#8） |

**对 PRD 的直接影响**：
- 经验加上"判据"和"风险类别"两个字段；
- 默认生效范围收窄；
- `forget` 之后要做验证；
- 接力卡要记录输入版本；
- 按需层降级。
