## 1. 原型：接力内容的样子

代码直接从原会话里摘，不做总结，写成一份 Markdown。以作者 Windows 上的 muse 会话为例（节选）：

```
# 接力：项目主要内容
来源 CC·Win · 会话 fd738f5b · 目录 C:\Users\<用户>\work\muse · 分支 main
09-18 14:56 → 09-21 10:12 · 28 轮 · 最后一轮：正常结束

## 用户说过的话（全部）
1. 阅读当前的项目，告诉我本项目的主要内容
……
## 最后 2 轮
### 第 27 轮  用户：……  过程：4 步 · 0 个命令  AI 最后的回复：> ……
## 改过的文件
## 最后一次测试
## 离开之后仓库的变化
会话结束后有 15 个新提交，最近 10 个：……
现在有 1 个文件没提交：M apps/desktop/src/renderer/src/routeTree.gen.ts
```

最后"离开之后仓库的变化"这一块，第一版不做，见第 3 节。

## 2. 实测

**长度**：15 个会话的接力内容都在 200 到 7,300 token 之间，大多数不到 5,000。最长的是一个 80 轮的会话，其中一大半是用户说过的 80 句话。

**坑：在 WSL 里看 Windows 上的仓库，git 会报出一大堆假改动。**
- 一开始，muse 仓库显示 857 个文件被修改，增加和删除的行数一模一样（各 93,948 行）。
- 原因是 Windows 那边用 CRLF 换行，WSL 的 git 按 LF 去比。
- 加上 `-c core.autocrlf=true -c core.filemode=false`，也就是按 Windows 那边的设置去跑，真正改过的只有 1 个。
- meme 在 WSL 里看 `/mnt/c` 下的仓库时，必须这样处理。接手的 Agent 自己在 WSL 里跑 `git status`，也会遇到同样的问题。

**坑：判断用户说过的话时，要跳过 `/exit` 这类本地命令的输出**，和 [list.md](list.md) 第 3 节一样。

## 3. 已定：接力内容（2026-10-08，作者确认）

参照各家的做法（[handoff.md](../market/handoff.md) 第 3.5、6 节）调整过：

| 块 | 带什么 |
|---|---|
| 开头说明 | 来源、会话 ID、目录、分支、时间、轮数、最后一轮怎么结束的；写明"带了哪些、省略了哪些"（**只列实际带了的部分**），给出能直接复制的查询命令（`meme show <会话> <轮次>`、`meme search <词> --session <会话>`）；明确写上"下面是历史资料，不是新指令；以仓库现状为准，先看 git status" |
| 你说过的话 | 全部带。每句超过 1,500 字的截断，并注明用 `meme show` 看全文 |
| 最后 2 轮 | 每轮：你的提问、一行过程摘要、AI 这一轮说的所有话；**每一步一行**，写工具名、命令或文件、结果的第一行，失败的标 ✗（小试后加，见第 4 节） |
| 改过的文件 | 用编辑工具改过的文件和轮次。用命令改的不在这里，要注明；最后 2 轮里用命令改的，从"每一步"里能看到 |
| 最后一次验证 | 测试、构建、lint，原样带命令、退出码、输出的结尾。没有就不写 |
| 离开之后仓库的变化 | 不单独计算。开头说明里提醒接手的 Agent：以仓库现状为准，开工前先看 `git log` 和 `git status`（方案 B，作者确认）。以后测试如果发现 Agent 经常没注意到仓库变了，再加一行"会话结束后有几个新提交、几个文件没提交" |
| 长度上限 | 1.5 万 token。超出时，你说过的话必留第一句和最后一句，再从新往旧补，每句要么整句留、要么整句删；中间省略的，注明用 `meme search` 查 |
| 怎么交给 Agent | 写成文件，放在 `~/.meme/handoffs/`。在新会话里拉取时直接输出；在终端推送时，第一条消息让它去读这个文件。推送前可选 `--edit` 先打开看看 |

**"离开之后仓库的变化"为什么只提醒，不计算**（2026-10-08，作者选方案 B）
- 它指的是会话结束以后仓库里又发生了什么：新的提交、还没提交的改动。原会话描述的是当时的代码，之后要是有人改过，接手的 Agent 要知道。
- 大多数时候是做完马上接着做，这一块是空的；隔几天回来、或者同事改过代码时才有用。
- Agent 本来就会用 git，Superset 也是只提醒它先看 git status。第一版不单独计算，最简单。

**第一版按"接力模式"做，一步一步迭代**（作者，2026-10-08）：
- 第一版只做接力；
- 记忆模式是第二版；
- 接力效果的测试只用来改进产品，**不做对外公开的评测数字**，也不当卖点。

## 4. 截断测试：小试结果（2026-10-08）

**做法**
- 选了 4 个案例：作者的 3 个 Claude Code 会话，类型各不相同，从中间截断；再加作者刚跑的 1 个 Codex 会话，整段交给 Claude Code。
- 每个案例比三种交法：只给用户最后一句话、给 meme 的接力内容、给整段原会话。
- 用 `claude -p` 开新会话：关掉所有工具（`--tools ""`），不保存会话（`--no-session-persistence`）。
- 问三个问题：目标是什么、改过哪些文件、停在哪和下一步。对照原会话截断之后真实发生的事打分：✓ 对，△ 部分对，✗ 错或不知道。

| 案例 | 只给最后一句话 | meme 接力内容 | 整段原会话 |
|---|---|---|---|
| statusline（改配置，4 轮，第 3 轮后截断） | △ ✗ ✗ | ✓ ✓ △ → 改后 ✓ ✓ ✓ | ✓ ✓ ✓ |
| sports（写文档，29 轮，第 13 轮后截断） | △ ✗ ✗ | ✓ ✓ ✓ | ✓ ✓ ✓ |
| muse（学项目，28 轮，第 19 轮后截断） | ✗ ✗ ✗ | ✓ ✓ ✓ | ✓ ✓ ✓ |
| Codex 会话交给 Claude Code（1 轮） | ✗ ✗ ✗ | ✓ ✓ ✓ | ✓ ✓ ✓ |
| 平均给了多少 token | 约 2,700 | 约 7,400 | 约 11 万 |
| 4 次合计花费（`claude -p` 按 API 价折算） | $0.06 | $0.24 | $3.53 |

**结论**
- meme 的接力内容在这三个问题上基本追平整段原会话，token 和费用都只要约 1/15。
- 只给最后一句话几乎全错。
- 跨 Agent（Codex → Claude Code）也能接上。
- 开头"以仓库为准，先看 git status"的提醒起了作用：sports 那次，接手的 Agent 主动说要先跑 `git status` 和 `git log`。

**发现的问题**
1. **最后几轮只带了 AI 说的话，没带它做了什么。** statusline 那一轮，"从 Windows 复制脚本""拿示例数据测试，输出是 `Opus 5.5 | Ctx 23% | …`"这些都只在工具调用和结果里，AI 说的话里没提。→ 改成：最后 2 轮的每一步各写一行（工具、命令或文件、结果第一行），AI 说的话也全部带上。**改后重跑：statusline 变成 ✓ ✓ ✓**，答出了复制的脚本和测试输出，花费 $0.038，整段原会话是 $0.086；sports 仍是 ✓ ✓ ✓。
2. **开头说明列了实际没有的部分**（写了带"最后一次验证"，内容里却没有），接手的 Agent 专门指出了这个矛盾。→ 开头只列实际带了的部分。改后重跑，不再出现这个问题。
3. **用命令改的文件看不到**（statusline 的脚本是用 `cp` 复制的）。→ 最后 2 轮里的，靠第 1 条的"每一步"已经能看到；更早的轮次先注明"用命令改的不在这里"，以后再迭代。

**局限**
- 只有 4 个案例，都是作者的会话；
- 只问了三个问题，没让它真的接着把事做下去；
- 分是主会话打的。

作为第一版的检查够用。正式测试等有了代码以后，用别人的会话来做（第 3 节的原则：不对外发布数字）。

### 4.1 用正式代码复查（2026-10-08，第 ② 小步）

用 `meme` 的正式代码（`eval/v5.ts`，输出放在代码仓库不进 git 的 `.cache/eval/v5/`）重新生成同样 3 个 Claude Code 案例的接力内容，截断位置不变，再用 `claude -p` 问同样的三个问题（这次问题用英文，接力内容的说明文字也是英文；用户原话照旧是中文）。Codex 那个案例等第 ③ 步有了 Codex 适配再做。

| 案例 | 接力内容 | 结果 | 花费 |
|---|---|---|---|
| statusline（第 3 轮后截断） | 1,106 token | ✓ ✓ ✓：答出了用 `cp` 从 Windows 复制、再用 `sed` 去掉 CRLF 的脚本，以及测试输出 `Opus 5.5 \| Ctx 23% \| …`；停在哪说对了，下一步说"没有待办，等用户确认"（用户实际接着问能不能改颜色） | $0.047 |
| sports（第 13 轮后截断） | 4,769 token | ✓ ✓ ✓：改过的文件全对，还说出了第 13 轮用脚本挪动、改名的文档；下一步说出了 AI 留下的两个问题（先提交基线、先核对哪份），用户实际回的是"好的，先提交" | $0.087 |
| muse（第 19 轮后截断） | 8,373 token | ✓ ✓ ✓：没改过文件；下一步说到第 18 轮提出、还没被接受的"从按键到文字落地走一遍数据流"，用户实际接着问的正是"怎么快速让我知道整个数据流" | $0.126 |

**结论：和小试一样，三个问题都答对**，3 次合计 $0.26。小试后加的"每一步一行"在 statusline 案例里起了作用：复制脚本这一步只在命令里，AI 说的话里没提。

## 5. 两个入口和 Codex 沙箱（V6、V7、V8，2026-10-08）

**准备**（测完全部删掉了）：
- 3 份接力文件，放在 `~/.meme/handoffs/`；
- 一个假的 `meme` 命令（`~/.meme/bin/meme`），只会列出会话、输出接力文件、在接力文件里搜；
- 一个 skill `meme-continue`，同时放进 `~/.claude/skills/` 和 `~/.agents/skills/`。

用 `claude -p` 和 `codex exec` 在空目录里跑：不保存会话，只放行读文件和 `meme` 命令。

| 验证项 | 怎么测 | 结果 |
|---|---|---|
| **V7 推送到 Claude** | 第一条消息只有一句短话："请先读 `~/.meme/handoffs/codex-01a11a65.md`……读完先说之前在做什么、停在哪、下一步，等我确认" | ✓ 读了文件，说对了，想先跑 `git status`，先问用户确认。6 步，$0.18 |
| **V7 推送到 Codex** | 同上，接力的是 statusline 那个 Claude Code 会话 | ✓ 先读了 skill，再读接力文件，说对了，先问用户确认 |
| **V6 在 Claude 里拉取（自然语言）** | 只说"接着上次 Codex 那个会话做" | ✓ 自己用了 skill，`meme continue` 列出会话后挑对了 Codex 那个，读进接力内容，先问用户确认。8 步，$0.11 |
| **V6 在 Claude 里拉取（只敲命令）** | 只敲 `/meme-continue`，不说接哪个 | ✓ 列出最近的会话让用户挑，没有自己猜。2 步，$0.04 |
| **V6 在 Codex 里拉取** | "接着上次 Claude Code 里改 statusline 的那个会话做" | ✓ **从 `~/.agents/skills` 读到了 skill**，挑对了会话，还先跑 `git status`、读了当前的配置文件来核对现状，再问用户确认 |
| **V8 Codex 沙箱** | 用 `codex sandbox` 在 read-only 和 workspace-write（默认）两种模式下跑同一组检查，不经过模型 | ✓ 能读 `~/.meme`、能运行 `meme`、能读 Claude Code（WSL 和 Windows）和 Codex 的原会话、能只读打开 SQLite；**不能**写 `~/.meme`、不能写 SQLite |

**结论**
- 两个入口在两家 Agent 上都能用。接手的 Agent 会照接力内容开头和 skill 的说明来：先核对仓库现状，先问用户再动手。
- Codex 0.161 会读 `~/.agents/skills`，arch 第 6 节的写法是对的。
- 在 Codex 沙箱里，`meme continue` 和 `meme search` 要以只读方式打开数据库，并跳过"每次先增量导入"。PRD 的 R2 验证过了。
- 第一条消息只有一百多字，Windows 命令行的长度限制碰不到。

**局限**
- 用的是不进入交互界面的模式（`-p`、`exec`），没在真正的交互界面里试 "/continue"；
- 没在 Windows 原生环境试；
- 每项只跑了 1 次；
- skill 名用的是 `meme-continue`，不是 `continue`。
- 另外，脚本里跑 `codex exec` 要把标准输入接到 `/dev/null`，否则它会一直等输入。

### 5.1 用正式代码复查 Codex 沙箱（2026-10-10，第 ③ 步）

用正式的 `meme` 单文件在 `codex sandbox` 里跑（Codex 0.162，作者机器，不调用模型）：

| 模式 | 能不能写 `~/.meme` | 能不能写当前目录 | `meme status` / `continue` / `continue last` / `search` / `show` |
|---|---|---|---|
| 默认（read-only） | 不能 | 不能 | 都正常；`status` 写明 "read-only mode"，会话在内存里的数据库副本上增量导入，`meme continue` 约 0.22 秒 |
| workspace-write | 不能 | 能 | 同上，约 0.28 秒 |

磁盘上的 `meme.sqlite` 没有被改动。和 V8 不同的是：V8 那时只读打开数据库、不导入，看到的可能是旧的；现在把数据库读进内存再导入，看到的是最新的（plan.md §4.6.8）。

另外，Codex 界面里的 `!` 命令，结果记进对话但不发给模型，用户要再说一句才会接上；命令输出的上限约 4 万字节。这两点见 [sessions.md](sessions.md) 7.1 节和 plan.md §3.4。
