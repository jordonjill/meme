## 1. Claude Code 的 `/resume` 长什么样

在作者本机用 Claude Code 2.1.294 运行 `claude --resume`，截下列表后直接退出：

```
Resume session
⌕ Search…
❯ Meme 第一版统一存储
  20 seconds ago · HEAD · 1.7MB
  记忆插件市场调研和差异化设计
  2 hours ago · HEAD · 9.8MB
  Statusline contents review
  1 week ago · HEAD · 352.4KB
  memory-system-expansion
  1 week ago · bg · HEAD · 5.6MB
Ctrl+A to show all projects · Ctrl+B to only show current branch · Space to preview · Ctrl+R to rename · Type to search
```

- 每个会话两行：第一行是标题，第二行是多久以前、分支、文件大小。
- 默认只列当前项目；Ctrl+A 看全部项目，Ctrl+B 只看当前分支，直接打字就能搜，空格预览，Ctrl+R 改名。
- **续接链会合成一个**：被续接过的旧会话（09-29 的 381dfa7f）没有单独列出。

## 2. cc-switch 怎么显示"最后停在哪"

看 v4.0.4 源码：
- **列表**：每个会话第二行写"最后：……"，取最后一条消息的开头（不分是用户还是 AI 说的，最多 160 字），和标题相同时不写。只截取，不判断。
- **阅读页的目录**：每一轮显示提问的开头（80 字内）、用了几步、几个失败、有没有最后回复、是不是被打断；有失败的轮次带红点。全部由代码统计。

## 3. 会话是怎么结束的（实测）

只看每个会话文件最后几条记录。这是读文件那一刻的结果，不是实时状态。

| 怎么结束的 | 个数 | 说明 |
|---|---|---|
| 正常结束，AI 给了回复 | 9 | —— |
| 最后是 `/exit` 这类本地命令 | 3 | 也是正常结束 |
| 被打断（用户按了 Esc，记录里有 `[Request interrupted by user]`） | 1 | —— |
| 没回完（停在工具调用或工具结果） | 1 | 这个会话后来被续接了，续接链合并后不单独显示 |
| 空会话 | 1 | —— |
| 正在运行（本会话） | 1 | 从文件看也是"没回完" |

**两个坑**
- **本地命令**：`/exit`、`/model` 这类命令的输出记成用户消息（带 `<local-command-stdout>`），不能当成"用户问了、AI 没回"。
- **正在运行的会话**：只看文件内容，分不出"停在半路"和"还在跑"，要靠最后修改时间来判断。

**结论**：按作者的用法，16 个会话里只有 1 个值得标出来，放进列表意义不大。会话怎么结束的，放到预览和第 4 步的接力里用。

## 4. 已定：`meme ls`（2026-10-08，作者确认）

1. **照 Claude Code `/resume` 的样子和按键**：
   - 每个会话两行：标题；多久以前 · 分支 · 文件大小；
   - 默认只列当前项目，Ctrl+A 看全部，打字搜索，空格预览；
   - 续接链合成一个；
   - 标题依次取用户改过的、Agent 自动生成的、第一条用户消息。
2. **每个会话标出来源**，也就是哪个 Agent、哪个环境（比如 `CC·WSL`、`Codex·Win`）：
   - 默认放在一起看，也可以按环境或按 Agent 切换、筛选；
   - 用**带颜色的短标签**（作者确认），不用 emoji 或特殊字体的图标。
3. **不显示"最后停在哪"**。会话怎么结束的（被打断、没回完），放在空格预览里写一行，第 4 步接力时也要用。
4. **Agent 来运行时，不进交互界面**，直接打印一份列表。比如在 Agent 里说"/meme"却没说接哪个会话时，就用这个方式列出来让用户挑。
5. **只在终端里显示**，第一版不做浏览器页面。
6. **在列表里选中一个会话，打开的是查看**（也就是 `meme show`），不是接力。
7. **2026-10-08 补**：当前项目没有会话时，自动改成列出全部项目，顶部写一行说明（见 [plan.md](../../design/plan.md) §3.1）。

## 5. 参照：Claude Code 怎么预览一个会话

在 `/resume` 列表里按空格预览，Claude Code 会把整段对话按它平时的界面重放一遍：
- 用户的话前面是 `❯`，AI 的回复前面是 `●`；
- 每次工具调用占一行，结果在下面用 `⎿` 只显示开头几行；
- 改文件时显示带行号的改动；
- 底部写"1w ago · 11 messages · HEAD"。

照这个思路，用作者 09-30 的 Statusline 会话做了两种样子（一次性脚本）：
- **A：一步一行**，和 Claude Code 的界面一样。能看清每一步，但长会话会非常长。
- **B：每一轮折成一行**，cc-switch 的做法。每轮只显示你的提问、"几步 · 几个命令 · 改了几个文件"、AI 最后回复的开头，一眼能看完整个会话。

**做样子时发现**：后台子代理完成时发回的通知（`<task-notification>`）在记录里是一条普通的用户消息，没有 `isMeta` 标记，一开始被当成了用户说的话。所以外层的"是否注入"要按 cc-switch 那样认全（见 [sessions.md](sessions.md) 第 6 节），至少包括：
- `isMeta`；
- 整条都是 `<system-reminder>` 的消息；
- `<task-notification>`；
- Codex 的 `# AGENTS.md instructions`、`<environment_context>`、`<user_instructions>` 和 developer 角色。

## 6. 已定：`meme show`（2026-10-08，作者确认）

1. **默认用 B，每一轮折成一行**，每轮带编号：

   ```
   Statusline contents review  [CC·WSL]
   ~/work/private · HEAD · 09-30 09:08 → 09:12 · 4 轮 · 352KB
    3 ❯ 不要显示这个，我要其他的，和我在win git bash下的那个一样……
        ▸ 9 步 · 6 个命令 · 改了 3 个文件
        ● 另外我记下了你的 Windows 配置位置……
   ↑↓ 选择 · Enter 展开这一轮 · / 搜索 · Esc 返回列表
   ```

2. **想深入看时，再展开**：
   - **用户自己看时，交互操作**：方向键选一轮，Enter 按 A 的样子展开成一步一行，再按一次收起；`/` 搜整个会话的全部内容（包括折叠起来的工具输出），搜到后跳到那一轮并自动展开；Esc 回到会话列表。
   - **Agent 来运行时，用命令**：
     - `meme show <会话>` 直接输出 B 的样子；
     - `meme show <会话> <轮次>` 输出这一轮的详细过程；
     - `meme show <会话> --full` 输出整个会话的详细过程。

     输出普通文字，不带颜色。
3. **展开以后怎么显示**：
   - AI 的回复显示全文；
   - 工具调用每次一行，结果只显示前 3 行，下面写"还有 N 行"；`--full` 时显示全部；
   - 系统注入的消息只留一行"⚙ 系统注入的消息（已隐藏）"，`--all` 时才显示内容；
   - 子代理只显示调用的那一行和它交回的结果，`--all` 时现读子代理的文件，把过程也显示出来；
   - 推理过程默认不显示，`--all` 时才显示；
   - 续接链整条连起来显示，每次续接的地方加一条分隔线。
4. **开头两行**：第一行是标题和来源标签；第二行是目录、分支、起止时间、轮数、文件大小。
5. **Codex 等其他 Agent 的会话，也用同样的样子显示。**

## 7. 实测：中文搜索怎么做

**Claude Code 和 Codex 怎么搜**：两家都不建索引，每次现扫文件里的内容。
- Claude Code 内置的 Grep 工具底层就是 ripgrep。本机 2.1.294 的程序里自带一份 rg，工具说明写着 "A powerful search tool built on ripgrep"。
- Codex 的提示词要求"搜文字或文件时优先用 `rg` 或 `rg --files`"。

**四种办法的对比**：在作者全部会话上测（3,820 条记录，约 520 万字）。表里是搜到几条 / 每次多少毫秒。

| 搜什么 | 逐条比对（标准答案） | trigram 索引 | trigram + 短词逐条比对 | 两字切分索引 |
|---|---|---|---|---|
| 接力（2 字） | 115 / 11ms | **0** | 115 / 11ms | 115 / 0ms |
| 会话（2 字） | 540 / 9ms | **0** | 540 / 9ms | 540 / 0ms |
| 统一存储（4 字） | 37 / 12ms | 37 / 0ms | 37 / 0ms | 37 / 0ms |
| 删（1 字） | 348 / 9ms | **0** | 348 / 10ms | 348 / 8ms |
| WSL 会话 | 95 / 5ms | **0** | 95 / 1ms | **94**（漏掉 "WSL2" 里的） |
| cleanupPeriodDays | 9 / 6ms | 9 / 0ms | 9 / 0ms | 9 / 0ms |
| 索引多大 | 不需要 | 19.6 MB | 19.6 MB | 5.4 MB |

- **逐条比对的速度会随数据量变化**：数据放大 10 倍（5,200 万字）是 70 毫秒，放大 50 倍（2.6 亿字）是 0.33 秒。
- **坑**：SQLite 的 `LIKE` 会把 `_` 当成通配符，搜 `secure_delete` 会把 `secure-delete` 也搜出来。要用精确包含（`instr`）或正则。
- **能不能让 Agent 直接用 rg 搜原会话文件**：用 grep 搜"接力"，0.08 秒命中 200 行，但每行是一整条 JSON 记录，平均 7,500 字、最长 3.9 万字，加起来有 1.5 MB；里面混着元数据、系统注入的消息、续接复制来的重复内容，也没有脱敏。`meme search` 搜同一个词，只剩 113 处有用的，每处只返回一行。

**搜索结果的样子**（用作者的会话搜"接力"，节选）：

```
$ meme search 接力
115 处命中，去掉续接复制来的和系统注入的，剩 113 处，在 3 个会话里

记忆插件市场调研和差异化设计  [CC·WSL]  10-08  70 处
  第  2 轮 工具：…可以把多个 agent 拉进群聊分工接力。 - **主动性来自例行任务和监控**…
  第 11 轮 AI：…作为第一卖点的场景：跨 Agent 接力 调研里有句用户原话："When you s…
  … 还有 67 处
  → meme show a08bde23 2
```

## 8. 已定：`meme search`（2026-10-08，作者确认）

1. **不建索引，每次逐条比对**，和 rg 一样。数据量大到明显变慢时再加索引，用法不变。
2. **用法照 rg 的习惯**：
   - 默认按正则匹配，普通的中英文词照样能搜；`-F` 按普通文字精确匹配；
   - `-i` 忽略大小写，`-C N` 多显示前后几行；
   - 不用 `LIKE`，因为它会把 `_` 当成通配符。
3. **搜哪些内容**：
   - 搜你的话、AI 的回复、工具调用和结果；
   - 系统注入的消息不搜；
   - 续接复制来的记录只算一次；
   - 子代理的过程不在镜像里，暂时搜不到。
4. **结果怎么显示**：
   - 按会话分组，最近的会话在前；
   - 每个会话最多列 3 处，每处一行：第几轮、谁说的、前后一小段；
   - 每组最后给出 `meme show <会话> <轮次>`。
5. **工具输出里的命中默认只显示个数**，加 `--all` 才逐条列出。
   - **2026-10-08 改**：工具调用里的命中也只显示个数，默认只列出用户和 AI 说的话（见 [plan.md](../../design/plan.md) §3.3）。
6. **默认只搜当前项目**；`-a` 搜全部项目；`--session <会话>` 只在一个会话里搜。
7. **自己看时**，可以用方向键选中一条，按 Enter 打开那个会话并展开那一轮；**Agent 来运行时**，输出普通文字。
8. **只读**，Codex 沙箱里也能用。

**对第 2 步的影响**：数据库里不再有全文检索索引，第 2 步定的"真删除时整理一次检索索引"也不再需要，删干净只靠数据库层的 `secure_delete`；数据库少了一半左右。
