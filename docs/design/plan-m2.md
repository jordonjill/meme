## 1. 这一版的做法

作者 2026-11-17 定：**先搭起框架，再做测试。**

- **框架**指的是：每一层都先有最薄的一版，一条记忆能从写入一路走到被 Agent 读到。先做不调模型的主干，再把流水线接上去。
- **测试放在框架之后**：评测集、真机测试、各种门槛和预算的调整，都等框架搭好再做。
- **单元测试只保骨架**：新模块写基本用例；现有的测试保持全过。

## 2. 分步（F1 到 F6）

每一步做完都能单独用，并且不破坏 0.1.0 已有的功能。

| 步 | 做什么 | 调模型 | 做完能用什么 | 对应草稿的 |

| **F1** | 目录和存储骨架：按层的文件夹；镜像挪到 `raw/sessions.sqlite`；跨进程的锁 | 否 | 和 0.1.0 一样用，数据在新位置 | M2-1 的一部分 |
| **F2** | 写入口：证据文件、结论文件、`apply()` 和各道门槛、快照、删除记录；`meme remember`；`meme memory` 的查看、追溯、删除 | 否 | 在终端里说"记住"，能看到它落在哪、从哪来，能删干净 | M2-2 |
| **F3** | 读：`derived/` 的索引；`meme context`、`meme recall` | 否 | 在 Agent 里用 `! meme context` 拿到记住的东西 | M2-2、M2-5 的一部分 |

| **F5** | 流水线骨架：模型的地址和 key；会话瘦身；阶段一、阶段二；水位线；`--dry-run`；顺带触发 | 是 | 会话静下来以后，自动提炼出证据和结论 | M2-3、M2-4 |

### F1 目录和存储骨架

**任务**
1. 一处定义数据目录里各层的位置（`raw/`、`evidence/`、`memory/`、`derived/`、`state/`、`FORMAT`），别处都从它取。
2. 镜像从 `~/.meme/meme.sqlite` 挪到 `~/.meme/raw/sessions.sqlite`：
   - 新位置没有就新建，内容照常从原会话重建；
   - 旧位置的文件（连同它的日志文件）在能写的时候删掉，删不掉不报错；
   - 只读的地方（沙箱）不删、不建，照旧在内存里工作。
3. `uninstall` 的清单、`install --dry-run` 的输出、README 里写到的路径跟着改。
4. 跨进程的锁：用"不存在才创建"的锁文件，带等待、超时和作废（草稿第 6.3 节第 1 条、第 9.3 节）。先只做出来并测好，F2 的 `apply()` 来用。

**验收**
- 现有的测试全过（改的只是路径）。
- 从 0.1.0 的数据目录升上来：运行一次以后，会话都在，旧文件不在了。
- 两个进程抢同一把锁，不会同时拿到；拿着锁的进程死了，另一个在超时以后能拿到。

### F2 写入口

**任务**
1. **证据文件** `evidence/<日期>.md`：一条证据怎么写成几行、怎么读回来；追加；按编号删除。日期按本机时区。
2. **结论文件** `memory/USER.md`、`RULES.md`、`EXPERIENCE.md`、`projects/<项目>/MEMORY.md`、`EXPERIENCE.md`：一条结论怎么写、怎么读回来。项目的文件夹名由 git 远程地址算出，没有远程地址才用根目录路径，并且在 Windows 上也合法。
3. **`apply()`**：所有写入都走它。拿锁；过门槛；存快照；先写证据，再写结论；版本号加一；中途失败就退回去。这一步做的门槛：
   - G1 格式和长度；G3 脱敏；G4 权限（不是用户发起的改动，不能动用户明确说过的条目）；G6 重复执行结果不变；G7 只能取代生效的条目；G8 原子。
   - G2 原文核对只留接口：现在只有命令行一种出处，原话就是内容本身。会话出处到 F5 才有。
   - G5 单批上限留参数，F5 的流水线才会用到。
4. **快照和删除记录**：`state/snapshots/` 留最近 20 批；`state/tombstones.jsonl`。
5. **`meme remember "<话>"`**：默认记成你对所有 Agent 的约定（`RULES.md`）；`--project` 记成当前项目的事实；`--about-me` 记成关于你的事实（`USER.md`）。不调模型，所以放哪个文件由你用选项说。
6. **`meme memory`**：列出；`meme memory show <编号>` 追到证据；`meme memory forget <编号>` 级联删除（结论、只属于它的证据、快照里的文字），留删除记录。
7. `FORMAT` 文件和 `state/version`。

**验收**
- `meme remember` 以后，证据文件和结论文件里各多一条，互相对得上；再说一遍同一句话，结论不会多一条，只多一条证据。
- 带密钥的话，进文件之前已经被遮掉。
- `meme memory forget` 以后，结论文件、证据文件、快照里都搜不到那句话；同一句话再由流水线提出来会被拦下，你自己再说一遍可以。
- 写到一半失败，文件和失败前一样。
- 只读的地方运行 `meme remember`，报一句清楚的话，不写任何东西。

**这一步不做的**：在 meme 之外手改文件以后的确认（`meme memory review`）；收件箱；索引。

### F3 读

作者 2026-11-17 说：整个设计不要有过多的规则；调整先不做，按顺序继续。所以这一步只做最薄的一版，能不加的机制先不加。

**任务**
1. **匹配**：一段话和一条结论有多相关。英文、路径、命令按词比；中文没有空格分词，按相邻两个字比。不调模型，不用向量。
2. **`meme context [<这次要做的事>]`**：输出交给 Agent 的参考内容。
   - 你的约定（`RULES.md`）、关于你（`USER.md`）、当前项目的事实（项目的 `MEMORY.md`）；
   - 给了"这次要做的事"时，再从其余结论里挑相关的几条；没有够相关的就不给；
   - 只给生效的条目；只适用于某个 Agent 的，只在那个 Agent 里给；项目的指令文件里已经有的不重复给；
   - 总长度有上限（草稿第 7.3 节的初始值），装不下的在最后说一句还有多少条。
   - 没有可给的内容时什么都不输出。
3. **`meme recall <词>`**：在记忆里找相关的结论，按相关程度排。
4. 两个命令都只读：不拿锁，不写任何文件，在沙箱里也能用。

**验收**
- `meme remember` 之后，在同一个项目里运行 `meme context`，能看到刚记住的约定和项目事实；换一个项目，只看到约定。
- 中文两个字的词（比如"限流"）能匹配上。
- 只读的地方两个命令照常工作。

**这一步不做的**：没做完的任务（F6）；注入记录（F4）；`derived/` 里的索引和预编译（见"做法和结果"）。

### F4 MCP

照"能不加的机制先不加"来做：先让任何支持 MCP 的 Agent 能读、能写同一份记忆，别的以后再加。

**任务**
1. **`meme mcp`**：一个走标准输入输出的 MCP 服务，随 Agent 启动、退出。只实现用得到的几样：握手、列出工具、调用工具。自己写，不引入新的依赖。
2. **四个工具**（草稿第 7.5 节列了 8 个，其余四个以后再加）：
   - `context`：开始任务前调用一次，拿到 `meme context` 的内容；
   - `recall`：按词找结论；
   - `explain`：一条结论的证据；
   - `remember`：记下用户说的、长期有效的东西。
3. **`remember` 的原话核对**：Agent 把用户的原话一起交上来；meme 到会话镜像里找，用户确实说过，就算"用户说的"，立即生效；找不到，就只算转述，先当候选，并在返回里告诉 Agent。这就是草稿里的 G2，原来打算 F5 才做，现在提前做最小的一版。
4. **服务说明**：告诉 Agent 开始任务前先调一次 `context`，用户要它记住东西时调 `remember`。
5. **`meme mcp --help`**：列出各家 Agent 接上它要运行的命令；`meme install` 加一行指过去。meme 自己不替用户登记（草稿第 7.6 节）。

**验收**
- 用一个最小的客户端按协议和 `meme mcp` 对话：握手、列出四个工具、四个工具都能调用。
- `remember` 带的原话在会话里找得到时，结论立即生效，证据指向那个会话的那一条消息；找不到时是候选。
- 标准输出里只有协议的消息，没有别的文字。

**这一步不做的**（都留到用得上的时候）
- 另外四个工具：`search`、`handoff`、`tasks`、`feedback`。
- **收件箱**：`remember` 直接走 `apply()`，它本来就拿锁，不需要先放进收件箱再收。
- **注入记录**：它是给"判断注入过的条目有没有用"准备的，那一块在框架之后。
- 在 `meme status` 里显示哪些 Agent 已经接上。

### F5 流水线

这一步把模型接进来。照作者的意思：判断交给模型，代码只保那几件模型保证不了的事。

**任务**
1. **模型的配置**：`config.json` 里的地址、key、模型名（也可以用环境变量）；接口用 OpenAI 兼容的对话格式。没配置就不联网。
2. **把会话整理成给模型看的文本**：一条记录一段，带上记录的编号；用户的话和 AI 的话保留，工具调用只留名字和关键参数，工具输出只留头尾；别的会话复制来的历史、系统注入的内容、推理过程不给。
3. **一次调用里让模型做完判断**：给它这段会话和这个项目现有的记忆，它回答要记哪些。每一条有：一句话、是事实还是经验、关于谁（约定、你、项目）、原话和原话所在的记录编号；它也可以说这一条取代了已有的哪一条，或者只是给已有的某一条多一份证据。
4. **代码做的事**：
   - 原话确实在它说的那条记录里，才收；不在就丢掉这一条。
   - 谁说的决定可信档：用户的话是"用户说的"，工具输出是"查得到"，AI 自己的话是"推断"。
   - 其余都交给 F2 的 `apply()`：遮密钥、不许改用户说过的、忘掉的不再学回来。
5. **读哪些会话**：静下来 2 小时以上、还没读过的；被排除的项目不读；第一次只读最近 14 天的，除非加 `--all`。读到哪了记在 `state/processed.jsonl`。
6. **`meme memory update`**：`--dry-run` 只列出要读哪些会话、大约多少 token，什么都不发；`--session <编号>` 只读指定的一个。

**验收**
- 用一个假的模型服务：它回答的条目里，原话在会话里的被记下来，原话是编的被丢掉。
- 同一个会话不会读第二遍；会话后来又有了新内容，只读新的部分。
- `--dry-run` 一个请求都不发；没配置模型时说清楚怎么配。
- 被排除的项目的会话，一个字都不发。

**这一步不做的**
- **两个阶段合成了一次调用**。草稿里是先逐个会话提炼、再每天按项目整合；现在让模型在读一个会话的同一次调用里，对着现有的记忆直接决定新增、取代还是补证据。跨会话的整合以后再说。
- **顺带触发**（别的命令运行时自动在后台起流水线）先不做，现在只有手动运行。
- 太短的会话的门槛、每次运行的 token 上限：先不设。

### F6 工作记忆和插件

**任务**
1. **没做完的任务**（工作记忆）：从会话镜像现算，不存。同一个项目里、最近 7 天内、最后一轮没有正常结束的会话，最多列 3 个。已经被别的会话接着做的、现在可能还在跑的、就是当前这个会话的，都不算。知道分支时只看同一个分支。
2. **`meme context` 带上它**：多一段 "Unfinished here"，每个任务一行，带上接着做要运行的命令。MCP 的 `context` 工具也一样。
3. **`meme context --hook`**：给 Agent 的 hook 用。从标准输入读 Agent 给的 JSON（当前目录、会话编号）；不管出什么错都安静地退出，不能挡住 Agent。
4. **`meme plugin`**：在 `~/.meme/plugins/<Agent>/` 里生成那家 Agent 的插件，并打印你要运行的安装命令。这一步只做 Claude Code 的：会话开始时的 hook 运行 `meme context --hook`，再带上 `meme mcp`。插件长什么样写在那家 Agent 的档案里。
5. `meme uninstall` 把生成的插件文件夹也删掉，并提示先在 Agent 里卸掉插件。

**验收**
- 一个被打断的会话，会出现在同一个项目的 `meme context` 里；做完的、别的项目的、正在跑的不出现。
- `meme context --hook` 收到乱七八糟的输入也是安静地退出，退出码 0。
- 生成的插件能通过 Claude Code 自带的校验命令（`claude plugin validate`）。

**这一步不做的**
- **第一条消息时的召回**（提问时的 hook）：先只做会话开始这一个 hook。
- **Codex 等其他家的插件**：它们的插件里能放什么还没查清（草稿 13.2 第 2 条）。
- **WSL 指向 Windows 的链接**：单独拿出来，原因见"做法和结果"。
- 另外四个 MCP 工具、顺带触发流水线：仍然留着。

### F7 装一次，两边都能用（2026-11-17 作者定，不属于记忆框架）

**背景**：记忆只有一份了，但程序还是"在哪装就在哪用"（D11）。要在 WSL 的 Agent 和 Windows 的 Agent 里都用 meme，两边要各装一遍；现在 `meme install` 只提示另一边的安装命令。作者定：安装时顺带问一句，要不要把另一边也装上。会话镜像和交接不搬（它们是缓存或现算的，SQLite 也不能跨系统共用）。

**任务**
1. **认出另一边的状况**：有没有 Agent、有没有装 meme、装的是哪个版本。
   - 从 WSL 看 Windows：以前看 Windows 用户目录里有没有 `.meme`。现在 WSL 的记忆也放在那里，这个办法不准了，改成看有没有程序本身，或者有没有它的会话镜像。
   - 从 Windows 看 WSL：照旧，到正在运行的发行版里找 `meme`。
2. **问了再装**：在终端里运行 `meme install` 时，另一边有 Agent 而没装 meme，就问一句；同意了，就在另一边运行那一侧自己的官方安装脚本，并指定和这边一样的版本。
3. **版本不一样时**：也问一句要不要把另一边换成这边的版本。
4. **不在终端里**（管道、Agent 里）：不问，照旧只打印另一边的安装命令。
5. `install.sh` 是从管道里读的脚本，它最后运行 `meme install` 时把终端交给 meme，这样用一条命令安装时也能被问到。

**验收**
- 用假的 `powershell.exe` 和假的 `wsl.exe`：回答 y 时，另一边的安装脚本被调用，带着这边的版本；回答别的或不在终端里时，不调用。
- Windows 用户目录里只有记忆、没有程序时，仍然认为那边没装。
- 两边版本一样时什么都不问。

**约束**：往另一个系统里放程序、改它的 PATH，每次都要先问。这一步不在本机真的运行（那会动作者真实的 Windows 用户目录），只用假的程序测。

## 4. 做法和结果

每一步做完，在这里记下做了什么、和计划不一样的地方、留下的问题。

### F1（2026-11-17 做完）

**这一步定下的细节**（草稿里没写到，或者写得不够细）

- **遗忘**：只属于这条结论的证据一起删；别的结论也在用的证据留着。快照里的那一条也删掉。删除记录里只有哈希。你自己再说一遍，删除记录就撤掉。

### F9 记忆自己形成，用户只看综述（2026-11-17 作者定）

**背景**：用真的模型（一个 OpenAI 兼容网关上的 qwen3.7-plus）试了一轮。作者看了以后定下产品的样子：**用户做自己的事，记忆在后台自己形成；用户不管理记忆的细节，隔一段时间看一份综述就够。** 每次都给理由太烦。

**任务**
1. **流水线自己启动**：会话开始时的 hook（`meme context --hook`）、`meme context`、`meme mcp` 启动时，如果配了模型、距上次整理超过 6 小时，就在后台另起一个 `meme memory update`。后台那一次最多读 20 个会话。可以用环境变量或配置关掉。
2. **`remember` 安静下来**：
   - 终端里只回一行："记下了：…"，或者"这句只针对这一次，没有记"。模型判断不该长期记的，不记，也不讲理由。`--as-is` 可以强制原样存。
   - MCP 的 `remember`：找到原话就当场回答"收到"，不等模型。请求先存进 `state/inbox/`，由后台写；中途断了，下次流水线接着处理。
   - 只有没配模型或模型出错时，才原样存原话。
3. **推断出来的要见过两次才生效**：依据是"推断"或"转述"的条目，证据来自两个以上不同的会话时，自动生效（memory.md v0.2 6.2 节）。
4. **`meme memory digest`**：自上次查看以来，新记下了哪些、取代了哪些、哪些还在观察、哪些没记。`meme status` 加一句"自上次查看以来新记了 N 条"。为此 `apply()` 每次改动都记一笔变化。
5. **提示词**：项目事实里不写项目名。

**验收**
- 配了假的模型时，运行 `meme context` 以后，后台的整理会自己发生；6 小时以内不会再起一次。
- "这次先别跑测试"这类话，模型不留时，记忆里没有它，综述里能看到"没记"。
- MCP 的 `remember` 不等模型就回答；后台处理完以后条目出现。
- 一条推断出来的经验，第二个会话里再出现时生效。
