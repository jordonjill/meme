## 0. 和 v0.2 比，改了什么

| # | 改动 | 为什么 |
|---|---|---|
| 1 | 记忆分三种：**事实、经验、工作**。v0.2 的"经验"拆成事实和经验；任务状态卡就是工作记忆 | 作者定的三分法，和综述 01 第 4 节一致 |
| 2 | 加一层**证据**：只追加，每条结论都指向证据；证据自带一小段原文 | v0.2 的证据只存指针，原文在镜像里；镜像跟着原会话走，Claude Code 默认 30 天清理，记忆就失去依据 |

| 4 | 记忆（`evidence/`、`memory/`、`state/`）和会话镜像**分开放** | `meme.sqlite` 是缓存，升版本就清空重建（D14、plan §4.4）；记忆要花模型调用生成，也是用户的东西，不能清 |

| 6 | 遗忘要**级联**，并且留一条删除记录 | 删除要传到所有层；标了失效，检索时要真的过滤掉 |
| 7 | WSL 和 Windows **只认一份记忆库**：放在 Windows，WSL 里的 meme 直接读写那里 | 两边的 Agent 要看到同一份记忆 |
| 8 | **meme 只写 `~/.meme`**（作者 11-17 定，D17 不变）：接入靠用户运行各家 Agent 自己的命令，meme 只把命令打印出来 | 不动用户文件（arch 原则 6）；装了什么、要删什么，一个目录就看得清 |

## 1. 三种记忆

| | 事实 | 经验 | 工作 |
|---|---|---|---|
| 回答什么 | 是什么、定了什么 | 在什么情况下该怎么做 | 现在做到哪了 |
| **靠什么证明它对** | 有人说过（用户原话），或者查得到（文件、命令输出） | 有结果为证：先失败后成功、用户纠正、测试由红转绿、改动被提交 | 会话本身 |
| 例子 | 回复用中文；不要自动 push；这个仓库用 pnpm；当初选 SQLite 是因为要单机部署；周五前交 M2 方案 | 跑 api 测试前先起数据库；Windows 上刚关掉的 SQLite 文件要重试几次才能删；改表结构要同时升版本号 | 目标、改过的文件、最后一次验证、卡在哪、下一步 |
| 范围 | 用户级、项目级 | 用户级、项目级，外加"只适用于某个 Agent" | 一个任务（一条会话链） |
| 保留多久 | 长期；被新事实取代才失效 | 长期；按效果（有用、有害）去留 | 任务结束就过期 |
| 谁生成 | 阶段一提出、阶段二整合；用户明说的可以走快速通道 | 同左，但只从带结果信号的片段里提 | 纯代码，从镜像现算 |
| 记错的代价 | Agent 理解错 | Agent 做错事，所以生效门槛更高 | 接错手 |

**边界规则（改 v0.2 4.2 节）**：v0.2 按"能不能写成'当……时要/不要……'"来区分事实和做法。现在改成按"**靠什么证明它对**"来区分：
- 有人说过或查得到的，是**事实**。用户的偏好和约定也算事实（属于用户级），比如"不要自动 push"。交给 Agent 时照样写成规则的口气，但它的对错看的是"现在还成不成立"，不看效果计数。
- 从结果里学到的，是**经验**。它有触发场景，能统计有用或有害。
- v0.2 的"能写成做法的优先写成做法"只管措辞，不再决定类型。

**经验细分为三档**（参考论文 MUSE；这个分法来自二手摘要，引用前要核对原文）：
- **策略**：怎么拆解、怎么验证，比如"改了解析器先跑真实会话测试"；
- **流程**：多步操作，超过字数上限的是 skill 候选（v0.2 4.3 节）；
- **工具**：某个命令或某个工具怎么用，常常只适用于一个 Agent。

第一版这一档可选，由模型填，不强制。

**和 v0.2 其他概念的对应**：
- 会话卡还是情景记忆，算在证据层旁边（第 3 节）。
- 用户画像还是由用户级事实编译出来的视图，不单独存。

## 2. 总体结构

```
写入来源   会话适配器（已有 4 家）· meme remember · MCP remember · 上传（逐字稿、笔记）
             │ 纯代码
L0 原料      raw/sessions.sqlite（各家 Agent 的对话，可重建）· raw/uploads/（你上传的材料）
             │ 阶段一：模型提议，代码核验
L1 证据      evidence/2026-11-17.md：每天一个文件，只追加。一句话 + 一小段原文 + 出处 + 说话人 + 可信档
             evidence/cards/：会话卡
             │ 阶段二：模型提议，代码核验
L2 结论      memory/USER.md、RULES.md、EXPERIENCE.md、projects/<项目>/…（唯一真源，人可读可改）
             工作记忆：从原料现算，不落盘（同 D18）
             │ 纯代码
L3 派生      derived/index.sqlite（全文检索、计数）· derived/compiled/（各家常驻内容）
             │ 都在 ~/.meme 里；Agent 每次运行 meme 命令现取
交付出口     MCP（meme mcp）· 命令行 · 插件里的 hook（也是运行 meme 命令）
```

- **一个文件夹就是一层**（作者 2026-11-17 定）。
- **只有 L2 是真源**，L3 可以整个删掉重建。
- L1 证据是 L2 的依据，只追加。有用、有害的计数从证据里的"反馈"条目算出来。这样就解决了 v0.2 5.5 节的问题：计数改动频繁，不放进版本管理；放进索引，会话被清理后又没法重建。
- 模型只出现在 L0→L1 和 L1→L2 两处，而且只提议；**落盘的永远是代码**。

## 3. 存储

```
~/.meme/
  raw/                      L0 原料
    sessions.sqlite           各家 Agent 的对话（会话镜像，就是 0.1.0 的 meme.sqlite）
    uploads/<内容哈希>.*       你上传的材料：逐字稿、笔记
  evidence/                 L1 证据：只追加
    2026-11-17.md             每天一个文件
    cards/<会话 id>.md         会话卡：每个会话一页纪要，跟着原会话走（v0.2 R4）
  memory/                   L2 结论：人能读、能改
    USER.md                   关于你（画像）：做什么、熟悉什么、用的电脑
    RULES.md                  你对所有 Agent 的约定：回复用中文、不要自动 push
    MEMORY.md                 跨项目的事实：共用的服务、团队的做法、长期在做的事；不在项目里的会话说的事（2026-11-18 加，plan-m2 F12）
    EXPERIENCE.md             跨项目的经验
    projects/<项目标识>/
      MEMORY.md               这个仓库的事实：命令、路径、架构决定
      EXPERIENCE.md           在这个仓库里学到的经验
  derived/                  L3 派生：整个删掉也能重建
    index.sqlite              全文检索、计数；以后要加向量也放这里
    compiled/<Agent>/         编译好的常驻内容：user.md、projects/<项目标识>.md
  state/                    管理：不属于哪一层，不能删
    inbox/                    还没处理的写入提议（MCP、remember）；每个进程写自己的文件，不抢锁
    deliveries/2026-11.jsonl  注入记录：哪次把哪些条目交给了哪个 Agent 的哪个会话
    processed.jsonl           处理到哪了（水位线）：哪个会话、处理到哪一条、用的哪版提示词
    tombstones.jsonl          删除记录：只存 id 和规范化文本的哈希，不存内容
    snapshots/                每批改动前的快照（13.1 第 3 条）
  plugins/<Agent>/          接线：给各家的插件，只有"运行 meme …"，没有记忆内容
  config.json               设置：模型地址、各项开关
  FORMAT                    evidence/、memory/、state/ 的格式版本；升级时迁移，不清空
  logs/、cache/             已有，不变
```

**meme 写的所有东西都在这个目录里**（Windows 上是 `%USERPROFILE%\.meme`）。卸载就是照 meme 打印的命令把各家的接入断开，再删掉这个目录。有 WSL 的机器上，记忆库放在 Windows 的这个目录里，WSL 用链接指过去（第 9 节）。

**三种记忆落在哪**：

| 记忆 | 文件 |
|---|---|
| 事实 | `memory/USER.md`、`memory/RULES.md`、`memory/MEMORY.md`、`memory/projects/<项目>/MEMORY.md` |
| 经验 | `memory/EXPERIENCE.md`、`memory/projects/<项目>/EXPERIENCE.md` |
| 工作 | 不落盘，每次从 `raw/sessions.sqlite` 现算 |

文件里的固定字样（类型、范围这些词）实现时用英文，这是仓库的规矩；本文为了好读写成中文。

### 3.1 原料 `raw/`

- **`sessions.sqlite`** 就是现在的 `~/.meme/meme.sqlite`，内容和规则都不变：它是缓存，升版本就清空，从原会话重建。挪位置的办法是新版本第一次运行时在 `raw/` 里重建，再删掉旧文件；`uninstall` 的清单跟着改。
- **`uploads/`** 按内容哈希存你上传的文件，旁边一份清单记原来的文件名和上传时间。上传的文件重建不出来，所以它**不跟着升版本清空**，只有 `meme forget` 才删。

### 3.2 证据 `evidence/`：每天一个文件

```markdown
# 2026-11-17

## 14:32 · Claude Code · meme · 会话 3f2a91c4
- e-91c0 · 事实 · 明确 · 用户 · 项目
  装依赖用 pnpm，不要用 npm
  > 以后都用 pnpm，别再用 npm 了（#412）
- e-a7d2 · 经验 · 查得到 · 工具输出 · 项目
  跑 api 的测试前要先启动数据库
  > connect ECONNREFUSED 127.0.0.1:5432（#431）
提炼：<模型名>，提示词第 3 版
```

- **日期按这句话说出来的那天**（本机时区），不按 meme 处理它的那天。meme 要等会话静下来才处理，会话被续上以后还会重新处理；按说话的日期，结果总是落回同一批文件。
- **重新处理不会写重**：证据的编号由出处和内容算出来，已经有的不再写。
- **只追加，唯一的例外是 forget**：重写那一天的文件，把那一条删掉。按天分文件，这一步只动一个小文件。
- **由代码按固定格式写，人只读**。想改就用 `meme memory forget`、`meme remember`；直接改这里的文件不算数。
- 和 Muse、OpenClaw 那种每日一记的区别：那边是 Agent 自己随手写的，这里只有代码核对过原话的条目才写得进去。
- **会话卡**放在 `evidence/cards/`：它和证据一样由阶段一产出，但跟着原会话走，原会话没了就删。

### 3.3 结论 `memory/`

一条一节，人能直接读，代码也能解析：

```markdown
## m-3f2a 装依赖用 pnpm，不要用 npm
- 类型：事实 · 范围：项目，所有 Agent · 依据：查得到 · 状态：生效
- 为什么：仓库里是 pnpm-lock.yaml；2026-09 起由 npm 改为 pnpm
- 证据：e-91c0、e-a7d2
- 取代：m-1b07
```

- **USER 和 RULES 怎么分**：两个都是用户级的事实。能写成"要／不要……"的约定进 `RULES.md`；关于你本人和环境的描述进 `USER.md`。`RULES.md` 是每家 Agent 常驻内容的第一段。
- **MEMORY（用户级）放什么**（2026-11-18 作者定，plan-m2 F12）：`USER.md` 只是你的画像。跨项目要记住的事（几个项目共用的服务、团队的做法、长期在做的事）进 `memory/MEMORY.md`。记忆里的"项目"只认 git 仓库：在家目录、某个应用的工作目录里开的会话不属于任何项目，里面说的事也进这里。
- **没有 SOUL**：SOUL 是某一个 Agent 的人格。meme 要接很多家 Agent，各家有自己的人格，不由 meme 来定。
- **经验条目多两行**："什么时候用"，以及按 Agent 分开的有用、有害计数。计数由代码算出来写进去，不由模型写。
- **在 meme 之外改动的内容，要你在终端里确认一次才算数。**
  - 原因：这些文件 Agent 也改得了，它和你用的是同一个账号的权限。如果"手改过就算用户确认"，Agent 就能冒充你。
  - 做法：`meme status` 提示"有 N 处改动等你确认"；你在终端里运行 `meme memory review` 逐条确认。它要求真的终端，在 Agent 的 shell 里运行不了。
  - 确认以后，这些条目记为"用户确认"，以后只有你能改（门槛 G4）。确认之前，交给 Agent 的还是上一次确认过的内容。

### 3.4 派生 `derived/`

> **2026-11-17 做 F3 时改了**：索引先不建。条目少的时候直接读 Markdown 文件、在内存里比就够了。中文按相邻两个字来比，不用下面说的三字分词，因为中文的词大多是两个字，三字分词搜不到。以后要加索引，也要用两个字的切法。详见 [plan-m2.md](plan-m2.md) F3 的"做法和结果"。

- **`index.sqlite`**：全文检索用 SQLite 的 FTS5，分词用 trigram。
  - 2026-11-17 在本机实测（Bun 1.4.2 自带的 SQLite 3.53.2，Linux）：中文、英文都能搜到。
  - 少于 3 个字的词搜不到，比如"测试"。这种查询要退回逐条比对，和现在 `meme search` 的做法一样（D16）。
  - macOS、Windows 的单文件里能不能用，还要测（13.2 第 8 条）。
- **向量先不做，位置留在这一层**：
  - 条目短，数量在几百到几千，里面多是文件名、命令这类词，关键词检索够用；
  - 向量要么下载一个本地模型，要么把内容发给外部接口，后者和"不联网"冲突；
  - 等评测里出现"换个说法就搜不到"的错题，再加。
- **`compiled/`**：按 Agent 编译好的常驻内容，每次结论层有改动就重新编译。

### 3.5 管理 `state/`

它不属于哪一层，也**不能删**：

| 文件 | 丢了会怎样 |
|---|---|
| `inbox/` | 还没处理的写入提议没了 |
| `deliveries/` | 没法判断注入过的条目有没有用 |
| `processed.jsonl` | 所有会话要重新处理一遍，重新花模型的钱 |
| `tombstones.jsonl` | 删掉的内容可能被再次提炼出来 |
| `snapshots/` | 不能回滚 |

**项目标识**：照 native.md 3.1 节第 7 条，用规范化的 git 远程地址；没有远程地址才用根目录路径。这样 WSL 里的 `/home/…/repo` 和 Windows 上的 `C:\…\repo` 只要是同一个远程仓库，就算一个项目。列表里的项目分组仍按 D12 不变。

## 4. 数据对象

### 4.1 证据（L1）

| 字段 | 说明 |
|---|---|
| id | `e-` 加短哈希，由出处和内容算出 |
| 种类 | 事实、经验、反馈（注入过的条目有用还是有害）、任务结论（任务结束时留下来的） |
| 内容 | 一句话 |
| 原文 | 出处里的原话，最多约 200 字，先脱敏；代码核对它确实在出处里 |
| 出处 | `会话:<会话 id>#<记录 uid 或序号>`、`上传:<内容哈希>#<行>`、`命令行:<时间>`、`MCP:<Agent>@<时间>` |
| 说话人 | 用户、Agent、工具输出、第三方（上传的逐字稿里别人说的） |
| 可信档 | **明确**（用户原话）> **查得到**（工具输出、代码探测）> **推断**（从行为里看出来的）> **转述**（Agent 说的、第三方说的、经 MCP 写进来的） |
| 范围 | 用户、项目:<标识>、Agent:<名字> |
| 时间、提炼者 | 发生时间；哪个模型、哪版提示词提的 |

- 这里的可信档就是 v0.2 的"依据"维度（明确、推断、代码探测），只是多了一档"转述"。
- **证据文件里没有"状态"这一项**，因为文件只追加，不能回头改。一条证据的原会话还在不在，查原料层就知道；被 forget 的证据直接从文件里删掉，并留一条删除记录。

### 4.2 结论条目（L2）

照 v0.2 4.3 节的清单，再加四项：
- 类型（事实、经验）；
- 取代关系（取代了谁、被谁取代）；
- 状态（候选、生效、被取代、退役、可能过时）；
- 是否用户确认。

### 4.3 工作记忆（不落盘）

由代码从镜像现算，复用接力的提取逻辑（`src/handoff/`）。一张任务卡包括：
- 项目、分支、Agent、会话链；
- 目标（第一条用户消息，或者后来重新说过的目标）；
- 改过的文件、最后一次验证命令和结果；
- 结束方式（做完了、被用户中断、出错、Agent 在等用户回答）；
- 有没有改了文件但没提交。

**什么时候算"没做完"**：最后一轮被中断或出错、Agent 在等用户回答、最后的测试没过，或者有未提交的改动。

**什么时候过期**：被另一个会话接着做了（续接链）、N 天没有动静（初始值 7 天），或者用户运行 `meme task done`。

**过期前留下什么**：阶段一处理这个会话时，会把值得留的内容提成证据。工作记忆自己什么都不存。

### 4.4 注入记录和反馈

- **注入记录**（`state/deliveries/`）：每次交付了哪些条目、交给哪个 Agent 的哪个会话、哪个版本的常驻内容。
- **反馈**：阶段一按 v0.2 4.5 节判断这些条目有用、有害还是没遇到，结果作为"反馈"种类的证据写进当天的证据文件。

## 5. 写入：只有一个入口

所有写入都先变成一份**提议**：一组操作，包括新增证据、新增、更新、取代、忽略、反馈、撤回。然后统一交给一个 `apply()` 函数，逐项检查：

| # | 门槛 | 内容 |
|---|---|---|
| G1 | 格式 | 字段齐全；正文不超过上限（v0.2：300 字符） |
| G2 | 原文核对 | 原文确实在出处里（宽松核对，允许空白、标点差异；v0.2 4.3 节）；对不上的证据丢掉 |
| G3 | 安全 | 先脱敏（复用 `src/redact/`）；"不抽取"的安全规则由代码强制执行（v0.2 4.4 节：读过不可信内容之后的回合不交给模型提炼） |
| G4 | 权限 | 推断不能取代明确；用户确认过的条目只有用户能改；转述只能进证据，不能直接生效 |
| G5 | 改动上限 | 每个项目每批的 L2 改动有上限（初始值 20 条），超出的部分只留着提议，等用户在 `meme memory review` 里看 |
| G6 | 幂等 | 同一份提议执行两次，结果不变（按内容哈希） |
| G7 | 取代链 | 只能取代已有的生效条目；新条目真正生效以后，旧条目才退役（v0.2 6.2 节细节 2） |
| G8 | 原子 | 先写证据，再改 Markdown，最后更新索引、重新编译常驻内容；中途失败就整批回到快照 |

**四个写入口**：

| 入口 | 谁用 | 走到哪一步 | 调模型 |
|---|---|---|---|
| **流水线** `meme memory update` | 顺带触发，或手动运行 | 阶段一 → 阶段二 → L2 | 是 |
| **快速通道** `meme remember "<原话>" [--project]` | 用户，在终端里或在 Agent 里用 `!` | 用户原话直接成为"明确"的证据，按 v0.2 6.2 节立即生效；下一次流水线再做去重 | 否 |
| **MCP `remember`** | 任何 Agent | 先进 `state/inbox/`，可信档是"转述"。如果 Agent 附上了会话里用户的原话，而镜像里核对得上，就升为"明确" | 否 |
| **上传** `meme memory upload <文件>` | 用户：逐字稿、笔记 | 原文件存进 `raw/uploads/`，然后照常走阶段一；第三方说的话算"转述" | 是 |

写成功以后才回复"记住了 m-xxxx"。没有一个入口能绕过 `apply()`。

## 6. 处理流程

### 6.1 阶段一、阶段二

照 v0.2 第 2、4、5 节：
- **读取**：会话静下来（2 小时）才处理；先瘦身，带上这次注入过的条目，以及最多 20 条相关条目。
- **阶段一**：产出会话卡、候选证据，以及对注入过的条目的反馈。
- **阶段二**：按项目整合，用新增、更新、取代、忽略四种操作。

v0.3 只改三处：
1. 阶段一的产出是 **L1 证据**，不再是"候选经验"。
2. **经验只从带结果信号的片段提**。没有信号的会话只提事实。这是综述 03 和自进化报告的共同结论：经验要有外部信号，否则反思会把错误固化下来。
3. 用**水位线**记录每个会话处理到哪；没有新内容就不调模型。

> **2026-11-17 作者同意改了瘦身的做法**：在本机最近 14 天的 13 个会话上量过，发出去的 258 万 token 里，用户的话只占 1%，AI 的回复 26%，AI 执行的命令 36%，工具输出 36%。现在只发用户和 AI 说的话；AI 每用一次工具只发一行（最多 200 字）；工具的输出只在失败时发（最多 300 字），因为经验大多来自失败；Agent 自己的任务清单、桌面版的界面工具不发。同样 13 个会话降到 102 万 token。原来"不因为不重要就去掉，只缩短"的做法不再适用。

### 6.2 进程：两条写入路，没有常驻服务

作者 2026-11-17 定。

**两条写入路**：

| 路 | 谁发起 | 什么时候 | 调模型 | 写到哪 |
|---|---|---|---|---|
| **当场写** | 正在用的 Agent 调 meme 的工具（MCP 的 `remember`、`feedback`），或者用户运行 `meme remember` | 对话当中 | 否 | 先进 `state/inbox/`。用户的原话核对得上就立即生效；Agent 自己说的只算转述，留在证据里 |
| **流水线** | meme 自己 | 会话静下来 2 小时以后 | 是 | 阶段一写证据和会话卡，阶段二写结论 |

**有哪些进程**。没有常驻服务，也不登记系统定时任务；每个进程都是某个人或某个 Agent 运行的一条 `meme` 命令：

| 进程 | 什么时候起 | 活多久 | 写什么 |
|---|---|---|---|
| 普通命令（`ls`、`search`、`continue`、`recall`） | 用户或 Agent 运行 | 一次命令 | 开头先做增量导入，写 `raw/sessions.sqlite`（0.1.0 就是这样） |
| `meme mcp` | Agent 启动时拉起 | 和那个 Agent 会话一样长 | 只往 `state/inbox/`、`state/deliveries/` 追加 |
| hook：`meme context` | 会话开始、第一条消息 | 一次命令，要很快 | 只往 `state/deliveries/` 追加 |
| `meme remember` | 用户运行 | 一次命令 | 经 `apply()` 写证据和结论 |
| `meme memory update`（流水线） | 见下面"流水线怎么起来" | 几分钟，要调模型 | 经 `apply()` 写会话卡、证据、结论、派生内容 |
| `meme memory upload`、`meme forget` | 用户运行 | 一次命令 | 经 `apply()` 存原文件，或级联删除 |

**流水线怎么起来**：
- **顺带触发**：任何 meme 进程启动时（`meme mcp` 启动、hook 运行、普通命令），看一眼水位线和上次整理的时间。距上次超过 6 小时、又有静下来的新会话，就在后台另起一个流水线进程。不用在系统里登记任何东西。
- **手动**：`meme memory update`。
- **系统定时任务**：meme 不替用户登记，因为那要往 `~/.meme` 以外写。`meme memory schedule` 只打印一行能直接用的 cron 或任务计划程序命令，由用户自己加。
- 没有配置模型（6.4 节）时，流水线不起来；当场写那条路照常可用。

### 6.3 六条规则

1. **只有 `apply()` 能改 `evidence/` 和 `memory/`**，改的时候拿一把锁文件（`state/` 里，"不存在才创建"）。
   - 调模型的那几分钟不拿锁，只在落盘那一下拿。
   - 落盘前先看版本号：别的进程在这期间改过结论，就重新检查这份提议（比如要取代的条目还在不在）。
   - 拿不到锁就等一会儿再试，有超时；锁放得太久（进程死了）按超时作废。
2. **其他进程只往 `state/` 里追加**：收件箱和注入记录。每个进程写自己的文件，不抢锁。
3. **每条 meme 命令开头顺带做三件事**：增量导入（现在就有）、收收件箱、看要不要起流水线。收收件箱不需要模型。
4. **流水线同时只有一个**（另一把"整理锁"）。每处理完一个会话就落盘一次；中途被杀掉，下次从水位线接着做。
5. **读永远不等写**。读的是本地的 `derived/`，版本号变了才重建。常驻内容在会话开始时定下来，这个会话里不再变（Hermes 的做法，不打破提示缓存）；后台改了的内容，下一个会话才生效。
6. **遗忘时先让流水线停下**，再级联删除。不然正在跑的流水线会把内容写回来（Muse 的教训）。

**和 Muse 不一样的一处**：Muse 每条记忆要另起会话核验一次、复核一次，存一条记忆要四五次模型调用。meme 的证据带原话和出处，"原话在不在出处里"由代码逐字核对，不再调一次模型。阶段二的改动要不要加一次模型复核，先不加，看评测结果再定。

### 6.4 模型：给 meme 配一个地址和 key

作者 2026-11-17 定：流水线可以调用大模型，记忆都存在本地。

**配置**（在 `config.json` 里）：

| 项 | 说明 |
|---|---|
| 地址 | 模型服务的地址。接口先支持 OpenAI 兼容的对话格式，多数服务商和本机的模型服务都能用；别的格式按需要再加 |
| key | 直接写在 `config.json` 里，或者只写一个环境变量的名字 |
| 模型名 | 用哪个模型。阶段一和阶段二先用同一个 |

**记忆都在本地，出去的只有一样**：流水线运行时发给这个地址的文本。

| | 内容 |
|---|---|
| 会发出去 | 瘦身、脱敏以后的会话文本；和它相关的已有条目（最多 20 条）；阶段二的候选证据和会话卡；正在处理的上传材料 |
| 不会发出去 | 没配置模型时，什么都不发；被排除的项目；原始的会话文件；别的项目的记忆 |

- **地址可以指向本机的模型服务**，那样什么都不出本机。
- **没配置就不联网**。列出、搜索、接力、`remember`、MCP 读取都不需要模型。
- meme 不收集数据，不向这个地址以外的任何地方发东西。

**怎么控制发什么、花多少**：
- `meme memory update --dry-run`：列出这次要处理哪些会话、大约多少 token，不发送。
- **默认处理所有项目，可以排除**（作者 2026-11-17 定）：配置里列出不发送的项目（比如公司的仓库）。这些项目照样能搜索和接力，只是不提炼记忆。
- **第一次要手动运行一次** `meme memory update`（本稿新加，13.4 第 1 条）：它列出要处理的项目和估算，并告诉你怎么排除。跑过这一次以后，流水线才会顺带触发。不然配好 key 以后流水线就在后台悄悄开始，没有机会看到它要发什么。
- **第一次只处理最近 14 天的会话**。更早的要加 `--all`，先给出估算，确认后才开始。
- **每次运行有上限**（会话数和 token 数），超出的留到下次。
- **太短的会话不处理**（门槛待实验）。
- 粗估（v0.2 第 2.2 节）：瘦身后的会话中位数约 4 万 token，100 个会话约 400 万输入 token。实际花费取决于选的模型，在 M2-3 的评测里实测。

**key 的保管**：
- `config.json` 只有本人可读；`meme status` 只显示 key 的最后 4 位。
- meme 把这个 key 的原文加进脱敏清单，所以它进不了镜像、证据和报告。
- 提醒：Agent 和用户用的是同一个账号的权限，读得到这个文件。这和别的工具把 key 放在配置文件里是一样的风险。

**出错怎么办**（出错就放行）：
- 网络或接口出错：这次流水线停下，水位线不动，记进日志；读取不受影响。
- 模型返回的格式不对：重试一次；还不对，就把这个会话记为失败并跳过，换了提示词或模型以后再试。
- 让模型输出 JSON，由代码校验，不依赖某一家特有的结构化输出功能。

**另外两种方式**：
- **在 Agent 里整理**（`meme memory pending` 输出待处理内容，Agent 写出提议，交给 `meme memory apply -`）：留作以后的可选项，给不想配 key 的人用。
- **无头调用已装的 Agent**（`claude -p`、`codex exec`）：不做，除非先核对完订阅条款（13.2 第 7 条）。

### 6.5 和主流做法的对照

写入有三种时机，成熟的产品都是第一种加第三种：

| 时机 | 谁写 | 代表 | meme |
|---|---|---|---|
| 对话里当场写 | Agent 自己用工具改记忆文件 | Claude Code 自动记忆、Hermes、Letta 主 Agent、Muse 主对话、OpenClaw 的每日记录 | 有，但很窄：Agent 只能递提议，不能直接改文件 |
| hook 实时采集 | 每轮或每次工具调用触发，交给本机常驻服务加工 | claude-mem、Hindsight、Mem0 插件 | 不需要：会话文件已经在磁盘上，读文件就是采集 |
| 事后后台整理 | 另起一个模型，空闲时或定时跑 | Muse 每小时的流水线、OpenClaw 的"做梦"、Letta 的 sleep-time agent、Codex（空闲 6 小时）、Gemini CLI（空闲 3 小时，要人批准） | 有：流水线。没有调度器，靠顺带触发 |

从别家学来的：
- **水位线之后没有新内容，整轮跳过**（Muse）。
- **模型只读，交结果，程序核对后写盘**（Muse 的 `finish_step`）。meme 把 Muse 漏掉的两条旁路也堵上：所有写入都过 `apply()`。
- **长期记忆只有一个写入者**（OpenClaw：MEMORY.md 只由"做梦"来写）。
- **常驻内容在会话开始时定下来**（Hermes）。
- **遗忘前先停后台任务**（Muse）。

meme 不需要的：
- **压缩前冲刷**（OpenClaw、Muse 都有）。压缩丢的是 Agent 眼前的上下文，会话文件里的原文还在（handoff.md 7.8 节核对过 Claude Code 和 Codex）。

依据：Muse 来自作者桌面上的两份拆解报告（10-26 到 10-29 的日志）；OpenClaw、Hermes、Letta 来自各自的文档（2026-11-17 查）；其余见 v0.2 第 3 节和 5.2 节。

## 7. 交付：怎么交给各家 Agent

### 7.1 三种记忆各走各的出口

作者 2026-11-17 定。还是 v0.2 6.3 节的三层，只是按记忆的种类分了工：

| 记忆 | 出口 | 理由 |
|---|---|---|
| 事实 | **常驻**：会话开始时给 | 是背景知识，稳定，量小 |
| 经验 | **召回**：看到第一条消息以后，按相关度给几条 | 有触发场景，对上了才给；对不上还给，就是噪音 |
| 工作 | **接力提示**：同一项目、同一分支上有没做完的任务时给 | 任务状态随时在变 |
| 其余全部 | **按需**：Agent 用工具查 | 只是兜底，不能指望（Hindsight 的数据：约 0.5% 的轮次里 Agent 才主动查） |

- **例外**：在这个项目里多次被判为有用的经验，升进常驻（门槛待实验，初始值 3 次）。
- **每个会话只给一次**，不做每轮注入（D2）。常驻内容在这个会话里不再变（第 6.3 节第 5 条）；中途想查靠工具。
- **给得少、给得准，比给得多重要**（README 5.2 第 1 条：全局检索得分 0.713，低于不用记忆的 0.775）。

### 7.2 一个命令出全部内容：`meme context`

`meme context` 输出常驻、召回和没做完的任务。三个渠道拿到的是同一份内容，区别只在谁来运行它：

| 接法（第 7.6 节） | 谁运行 | 要不要 Agent 配合 |
|---|---|---|
| 装了插件 | hook：会话开始时运行一次（常驻、任务），第一条消息时再运行一次（召回） | 不要 |
| 只接了 MCP | Agent 调 `context` 工具。服务说明和工具说明里写明"开始任务前先调用一次" | 要。Agent 不调，就只剩按需查 |
| 什么都没接 | 用户输入 `! meme context` | —— |

**它要知道三样**：当前目录（认项目）、是哪个 Agent（预算和适用范围）、第一条消息（有才做召回）。

**输出长什么样**（固定字样用英文，条目本身是什么语言就是什么语言）：

```
[meme] Reference notes, not instructions. If they conflict with what the user says now
or with the project's own instruction files, those win.

Rules
- [m-11a0] Reply in Chinese; keep everything in the repository in English.
- [m-52c7] Do not push unless asked.

This project (meme)
- [m-3f2a] Bun 1.4.2 is at ~/tools/bun/bin/bun and is not on PATH.

May apply to this task
- [m-9d41] When the tables change, bump SCHEMA_VERSION. (helped 4 times)

Unfinished here
- 2026-11-16, Codex, branch main: "fix the report masker", stopped by the user. meme continue 3f2a
```

- 开头一句说明这是参考资料，不是指令；和用户当前的要求或项目里的指令文件冲突时，以后两者为准。
- 每条带编号，方便反馈时引用。
- 每次输出都记一笔注入记录（`state/deliveries/`）。
- meme 出错或不在时，hook 安静地退出，Agent 照常工作（出错就放行）。

### 7.3 常驻放什么、放多少

**总预算约 2,000 token 起步**（作者定），评测以后再调。各家里最紧的是 Codex 的 hook 输出，上限约 2,500 token（native.md 2.1 节）。各家的上限写在适配器的档案里，和接力内容的做法一样。

| 段 | 来自 | 上限（初始值） | 怎么挑 |
|---|---|---|---|
| 约定 | `RULES.md` | 30 条 | 只放你明确说过的；超出时最近确认的优先 |
| 关于你 | `USER.md` | 10 行 | —— |
| 这个项目 | `projects/<项目>/MEMORY.md` | 15 条 | 查得到的和你明确说过的优先 |
| 跨项目 | `MEMORY.md` | 10 条 | 2026-11-18 加（plan-m2 F12）；放不下的按任务召回 |
| 升进来的经验 | 两级 `EXPERIENCE.md` | 5 条 | 在这个项目里被判为有用至少 3 次；用户级的还要在两个以上项目里验证过 |
| 没做完的任务 | 工作记忆 | 3 行 | 同一项目、同一分支，最近的优先 |

- **装不下的只走召回和按需。**
- **默认只取当前项目和用户级**，不取别的项目的。
- **只适用于某个 Agent 的条目，只给那个 Agent。**
- **转述来的内容不经你确认，永远不进常驻**（第 10 节）。
- **重复的不放**：输出时读一下当前项目的指令文件（CLAUDE.md、AGENTS.md），和里面重复的条目不再放。meme 不动这些文件，也不动各家自带的记忆。
- **预编译**在 `derived/compiled/<Agent>/` 里，hook 运行时只是读出来，所以快。

**常驻不放静态文件的代价**（和 native.md 的推荐相比）：
- 常驻内容不再由 Agent 自己读静态文件，而是每次开会话运行一条命令。
- 要靠插件处于启用状态，或者靠 Agent 照说明去调 `context`。
- 想要静态文件的用户可以自己加一行引用，meme 只告诉他们怎么写：Claude Code 在 `~/.claude/CLAUDE.md` 里加 `@~/.meme/derived/compiled/claude-code/user.md`；OpenCode 在配置的 `instructions` 里指向 `~/.meme/derived/compiled/opencode/user.md`。文件本身还是在 `~/.meme` 里。

### 7.4 召回怎么挑

不调模型，不用向量：

1. **取词**：从第一条消息里取文件路径、命令、报错、标识符；其余文字切成片段。
2. **检索**：在当前项目和用户级的条目里做全文检索（第 3.4 节）。检索的范围是正文、"什么时候用"和触发词。
3. **排序**：按相关度和"有用减有害"。
4. **最多给 5 条。没有够相关的，就一条都不给**（门槛待实验）。
5. 已经在常驻里的不重复给。

**触发词**：流水线写入一条经验时，让模型顺手写几个触发词（中英文、同义说法）。它们只放进索引，不放进给 Agent 的内容。贵的事放在写入时做，读的时候不调模型。

**已知的代价**：
- 关键词召回会漏。触发词能补一部分；补不上的，等评测决定要不要加向量（13.1 第 14 条）。
- 每个会话只召回一次。做到一半才出现的场景帮不上，除非 Agent 自己查。
- 只接了 MCP 的 Agent 要靠它听话：它不调 `context`，常驻和召回都拿不到。
- 常驻和召回的内容会进各家 Agent 的上下文，也就是会发给各家的模型服务商。项目记忆只在那个项目的会话里给。

### 7.5 MCP 工具（对外契约，带版本号）

| 工具 | 作用 |
|---|---|
| `context(cwd, first_message?)` | 开始任务前调用一次：常驻、召回、没做完的任务，一次给全（第 7.2 节） |
| `recall(query, project?)` | 会话中途查：取相关的事实和经验，附编号和理由 |
| `search(query)` | 搜原始会话，就是现有的 `meme search` |
| `explain(id)` | 一条记忆的证据、原文、取代链 |
| `tasks(project?)` | 没做完的任务（工作记忆） |
| `handoff(id)` | 接力内容，就是现有的 `meme continue <id>` |
| `remember(text, scope?, quote?)` | 写进 `state/inbox/`，可信档是"转述" |
| `feedback(id, helpful/harmful, reason)` | 写进 `state/inbox/`；整理时成为一条"反馈"证据，可信档是"转述" |

- **没有删除工具**：删除只能由用户在命令行里做。
- **工具一共 8 个，说明要写得短**：每个工具的说明都常驻在 Agent 的上下文里。
- `meme mcp` 是 stdio 服务，随 Agent 启动、退出，不常驻；只读打开索引，只追加写 `state/inbox/`。
- MCP 服务的说明（instructions）：Claude Code 会把它放进系统提示（2.1.308 里实际看到），里面写"开始任务前先调用一次 `context`"；放得下的话，再带上 `RULES.md` 的前几条。长度上限待查。Codex 不适合用它当常驻内容（native.md 2.1 节）；其他家要逐个查。
- `meme mcp` 在连接时记下是哪个客户端连进来的（MCP 握手里带客户端的名字）和时间，存在 `state/` 里。`meme status` 靠它显示哪些 Agent 已经接上，不用去读各家的配置文件。

### 7.6 怎么接上各家 Agent：meme 只写 `~/.meme`，接入由用户运行一条命令

**规则（作者 2026-11-17 定，D17 不变）**：
- meme 自己只往 `~/.meme` 里写。
- 接一家 Agent，就是用户运行那家 Agent **自己的**命令；改配置的是那家 Agent，不是 meme。`meme install` 发现本机的 Agent 以后，把每家要运行的命令打印出来。
- 接进去的只有接线：MCP 服务是 `meme mcp`，hook 运行的是 `meme context`。**记忆内容永远从 `~/.meme` 现读**，所以记忆更新以后不用重新接。
- 断开也一样：`meme uninstall` 打印要运行的命令，然后删掉 `~/.meme`。

**三种接法**：

| 接法 | 用户要做的 | 得到什么 |
|---|---|---|
| **A. 什么都不接** | 无 | 在 Agent 里用 `!`，或让 Agent 用 shell 运行 `meme context`、`meme recall`、`meme continue`（和现在用 `meme continue` 一样） |
| **B. 接 MCP** | 一条命令 | Agent 开始任务前调一次 `context`，拿到常驻、召回和没做完的任务（要靠 Agent 照说明去调）；按需查、写入、接力 |
| **C. 装插件** | 两条命令 | B 的全部，再加：hook 在会话开始和第一条消息时运行 `meme context`，不靠 Agent 配合；一个 skill |

插件由 meme 生成在 `~/.meme/plugins/<Agent>/`，用户用那家 Agent 的插件命令从这个本地目录安装。Agent 会把插件复制进自己的缓存，那是 Agent 写的。插件里只有接线，所以这份副本只在接线变了的时候才需要更新。

**各家的命令**（2026-11-17 在本机用 `--help` 核对过这些命令存在；还没有实际接过）：

| Agent（本机版本） | B. 接 MCP | C. 装插件 | 会话适配器 |
|---|---|---|---|
| Claude Code 2.1.308 | `claude mcp add -s user meme -- meme mcp` | `claude plugin marketplace add ~/.meme/plugins/claude-code`，再 `claude plugin install meme@meme` | 有 |
| Codex 0.162.1 | `codex mcp add meme -- meme mcp` | `codex plugin marketplace add`（支持本地目录）、`codex plugin add`；hook 第一次要用户审核信任；插件里能放什么待查 | 有 |
| OpenCode 1.19.0 | `opencode mcp add`（交互式） | 它的插件是配置目录里的代码文件，能不能从别的目录加载待查 | 有 |
| Pi 1.2.0 | 自带 MCP 支持，怎么登记待查 | `pi install <来源>` 装扩展，本地目录行不行待查 | 有 |
| WorkBuddy | 界面里：插件 → MCP 服务器 → 配置 MCP，粘贴 JSON；配置文件是 `~/.workbuddy/mcp.json` | 它的命令行引擎能从本地目录装插件；桌面版认不认待查 | 还没有。会话的位置和格式已经查到，见本节末尾 |
| 其他 MCP 客户端 | 在它的 MCP 设置里填 `meme mcp` | —— | —— |

- **写入的两条路不变**：有会话适配器的，被动收集，不需要 Agent 配合，最完整；只接了 MCP 的，只有 Agent 主动写的才有，可信档是转述。
- Cursor 会加载 Claude Code 的插件（native.md 3.1 节第 4 条），所以 meme 的 Claude Code 插件在 Cursor 里必须什么都不做。
- WSL 和 Windows 上的 Agent 各接各的，命令一样。

**WorkBuddy 查到了什么**（2026-11-17。本机没装 WorkBuddy，下面来自 memmy 的源码和 WorkBuddy 的官方文档，没有在真实文件上核对）

- **会话在哪**：`~/.workbuddy/projects/<项目文件夹>/<会话 id>.jsonl`，旁边有一个 `<会话 id>.meta.json`，里面的 `cwd` 是工作目录。根目录可以用环境变量 `WORKBUDDY_CONFIG_DIR` 或 `CODEBUDDY_CONFIG_DIR` 改。（memmy 的读取器）
  - 它的命令行引擎 CodeBuddy Code 用的是 `~/.codebuddy/projects/`，也是一个会话一个 `.jsonl`。（官方文档）
  - 一篇第三方文章说海外版的根目录是 `~/.workbuddy-ai`，没核实。
- **格式**：JSONL，一行一条。目录的样子像 Claude Code，**记录的格式不是**，更像 OpenAI Agents 的条目：
  - `message`：`role` 是 `user` 或 `assistant`，`content` 是一组 `input_text` 或 `output_text`；
  - `function_call`：`callId`、`name`、`arguments`（一个 JSON 字符串）；
  - `function_call_result`：`callId`、`status`、`output`；
  - 还有 `reasoning`、`file-history-snapshot`；
  - 每条带 `id`、`sessionId`、`timestamp`（毫秒）；
  - 用户消息里真正的问题包在 `<user_query>` 里，外面的 `<system_reminder>` 等几段要去掉；压缩之类的内部消息用 `providerData` 标出来。
- **所以要给它写一个新的适配器**（第五家），trajectory 0.4.3 不认这种格式。memmy 是 MIT 协议，它的读取器在 `Memory/src/agent-source/adapters/workbuddy/`，可以参考。
- **接 MCP**：界面里"插件 → MCP 服务器 → 配置 MCP"，粘贴 JSON。用户级的配置文件是 `~/.workbuddy/mcp.json`，写法是 `{"mcpServers": {"meme": {"command": "meme", "args": ["mcp"]}}}`。（官方文档）另有一个第三方项目说桌面版启动时会删掉这个文件、只能在界面里加。两种说法冲突，要在真机上看。
- **skill**：`~/.workbuddy/skills/<名字>/SKILL.md`。memmy 接 WorkBuddy 只用了 skill，没用 hook。
- **hook 和插件**：命令行引擎的 hook 和 Claude Code 很像。`SessionStart`、`UserPromptSubmit` 都能往对话里加内容；插件可以带 hook；`/plugin marketplace add <本地目录>` 能从本地目录加（目录里要有 `.codebuddy-plugin/marketplace.json`），再 `/plugin install <名字>@<市场>`。文档没写 hook 输出的长度上限。**桌面版认不认这些，没查到**：它的文档里没有 hook 这一页。
- **它自带的记忆**：每晚从会话历史里提炼事实、偏好、人物关系和待跟进的事，生成一份记忆摘要；用户可以让它记住或忘掉，也能从别的 AI 导入记忆。文档没说存在哪个文件。

来源：[memmy 的源码](https://github.com/MemTensor/memmy-agent)（提交 e640129，2026-11-12）；WorkBuddy 文档的 [hook](https://www.workbuddy.ai/docs/cli/hooks)、[目录结构](https://www.workbuddy.ai/docs/cli/codebuddy-dir)、[插件市场](https://www.workbuddy.ai/docs/cli/plugin-marketplaces)、[MCP](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)、[记忆](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)。

## 8. 遗忘与失效

| 情况 | 怎么处理 |
|---|---|
| 原会话被 Agent 自动清理，或者被用户在外面删掉 | 镜像照常跟着删（已有）；证据照样留着，**原文片段保留**，记忆不受影响，`explain` 里会注明原会话已经不在。meme 分不清是自动清理还是用户有意删的，所以默认保留 |
| `meme forget <会话>`（已有命令，扩展） | 级联：从每天的证据文件里删掉这个会话来的条目（只重写那几天的文件）→ 证据全没了的结论退役，并从当前文件和所有快照里删掉文字 → 重建派生层 → 写删除记录。上传的材料同理，连 `raw/uploads/` 里的原文件一起删 |
| `meme memory forget <m-id>`（新） | 结论退役并删掉文字，相关证据从证据文件里删掉，写删除记录。以后提炼出同样的内容（规范化文本哈希相同），G 门槛直接拦下 |
| 被取代 | 旧条目状态改为"被取代"，**召回、常驻、搜索都过滤掉**；`explain` 里能看到演变过程 |
| 可能过时 | 照 v0.2 4.3 节：正文里提到的文件、命令已经不存在，就降权；下次遇到相应场景时让模型再确认一次 |
| 按来源整批撤回 | 照 v0.2 4.1 节：某个 Agent 被投毒，就撤回它贡献的全部证据 |

## 9. WSL 和 Windows：记忆只有一份，放在 Windows 这一侧

作者 2026-11-17 定，同一天做完（plan-m2.md F6）。这一节取代了当天早些时候"每个文件夹各做一个链接"的方案。

### 9.1 规则

- **一台机器、一个人，只有一份记忆。**
- **有 Windows 的机器上，记忆放在 Windows 用户目录的 `.meme` 里**，在 WSL 里运行的 meme 也读写这一份。理由（作者）：用户一定有 Windows，不一定用 WSL；WSL 随时能读写 Windows 的盘，Windows 要读 WSL 得等它在运行。
- **程序还是装在哪边就在哪边运行**（D11 不变）。WSL 里的 meme 照常在 WSL 里跑，缓存也留在 WSL：会话镜像是 SQLite，跨系统的 SQLite 锁不可靠（plan §4.7）。
- 只有 Linux 或 macOS 的机器，全部在本地。

| 东西 | WSL 里的 meme 把它放在哪 |
|---|---|
| 证据 `evidence/`、结论 `memory/`、`state/`、`FORMAT`、`config.json` | Windows：`C:\Users\<用户>\.meme\`（在 WSL 里是 `/mnt/c/Users/<用户>/.meme/`） |
| 会话镜像 `raw/sessions.sqlite`、日志、`cache/`、`plugins/` | WSL：`~/.meme/` |
| `~/.meme/store` | WSL 里的一个链接，指向 Windows 那个文件夹 |

**那个链接有两个用处**：记下"记忆放在哪"这个决定，以后不用再判断；人在 WSL 里想看文件时，从 `~/.meme/store/` 进去就是。代码不靠它读写文件，读写用的都是真实路径，所以不存在"链接被删掉、换成了真文件夹"以后两边各写各的问题。

### 9.2 怎么认出是哪个 Windows 用户

1. WSL 的 `~/.meme/store` 已经有了：就用它指的地方。
2. 没有：看 Windows 的 `Users` 下面哪些文件夹是某个人的家（里面有 `.meme`、某家 Agent 的文件夹，或者 `AppData`；`Public`、`Default` 这些不算）。
   - 只有一个：就是它。
   - 有好几个：问一次 Windows 当前用户是谁（通过 WSL 运行一次 `cmd.exe`）。
   - 一个都没有，或者问不出来：记忆留在 WSL 本地，也不建链接，下次再判断。
3. 定下来以后建链接，以后不再变。

**链接指的地方够不着时**（比如 Windows 的盘没挂上）：报错，不写。不能悄悄在 WSL 里另起一份。

**两个环境变量**：设了 `MEME_HOME`，记忆就跟着放在那个文件夹里；`MEME_STORE` 可以直接指定记忆放在哪。

### 9.3 两边同时写，怎么不乱

- 记忆都是纯文本文件。写的时候拿锁文件（"不存在才创建"），整个文件先写在旁边再挪过去，挪不动就重试。
- 2026-11-17 的两次实测：

| 试了什么 | 结果 |
|---|---|
| Python（WSL）和 PowerShell（Windows）抢同一把锁文件，抢到的给计数器加一 | Windows 497 次，WSL 20 次，计数器正好 517，一次没丢。WSL 抢得慢得多，所以代码里带等待和超时 |
| Windows 上有程序开着一个文件时，WSL 去替换它 | 对方不允许删除时失败，允许时成功。所以替换要重试 |
| meme 自己（WSL）把记忆放在 Windows 盘上的临时文件夹里：十个进程同时 `meme remember` | 十条全都写进去了，没有报错，锁没有留下。之后列出、遗忘都正常；遗忘以后所有文件里都搜不到那句话 |
| 同上，从 Windows 那边看这些文件 | 读得到，是 UTF-8、LF 换行 |

**还没试的**：
- Windows 上的 meme.exe 和 WSL 里的 meme 同时写（现在只试了 WSL 这一边的多个进程）。
- 拿着锁的进程死掉以后，另一边靠超时接管（单元测试里有，跨系统没试）。
- 真的放进 `C:\Users\<用户>\.meme`：测试用的都是临时文件夹。

### 9.4 卸载

- 在 WSL 里卸载：删掉链接和 WSL 自己的缓存，Windows 那边的记忆不动。
- 在 Windows 上卸载：现在也不删记忆（记忆文件被当成"别的文件"留下）。卸载时记忆到底怎么处理，还没定（13.4 第 11 条）。

**D11 要跟着改一句**。原来是"跨系统只读、不跨系统写"。现在是：跨系统不写 SQLite；记忆是纯文本，WSL 里的 meme 可以写到 Windows 那一份里，写的时候拿锁文件。

## 10. 安全

- **记忆投毒**：记忆会交给所有 Agent，所以：
  - 只有"明确"和"查得到"的能立即生效；
  - 推断要在两个以上会话里出现过（v0.2 6.2 节）；
  - 转述（Agent 说的、第三方说的、MCP 写入的）不经用户确认，永远不进常驻；
  - 读过不可信内容之后的回合不交给模型提炼。
- **进记忆之前先脱敏**，交付之前再检查一次。
- **隐私**：v0.2 4.4 节"和写代码无关的个人信息不记"照用。上传的逐字稿里第三方说的话只进证据，关于第三方本人的内容不记，不进常驻（13.1 第 8 条）。
- **交付时标明是参考资料**，不是指令（第 7.2 节）。
- **会话文本会发给模型**：只在流水线运行时，只发给用户自己配置的地址，发之前先瘦身、脱敏；可以排除项目，可以先 `--dry-run` 看要发什么（第 6.4 节）。

## 11. 评测（在调用模型的功能之前做）

| 对象 | 怎么测 |
|---|---|
| 事实 | 照 LongMemEval 的题型：单会话提取、跨会话、知识更新（取代）、时间、该说"不知道"时说不知道；另外加遗忘题：forget 之后召回、常驻、搜索都不能再出现 |
| 经验 | 同一批任务分有记忆和没有记忆两组对比，**任务顺序打乱**（自进化报告：打乱后 AWM、ReasoningBank 都不如没有记忆）；统计跨 Agent 迁移有没有用 |
| 工作 | 复用接力的测试（V5） |
| 写入 | L2 条目里证据核对得上的比例要是 100%（Muse 约八成条目没经过核验）；G 门槛逐条有单元测试 |
| 成本和速度 | 每个会话的模型费用；召回延迟（hook 里要很快，目标 200 毫秒以内） |
| 出错归因 | 答错的题按环节归到抽取、核验、整合、检索、交付、回答 |

数据有两份：
- **合成会话**：埋好事实、更新、矛盾、删除，放在仓库里；
- **本机真实会话**：只在本地跑、只打印分数，和 `MEME_REAL_SESSIONS` 的做法一样。

## 14. 附：同类的记忆插件

2026-11-17 查。依据有三样：作者的 landscape.md 第 2 节和 handoff.md 第 8 节（10 月初）；各项目自己的文档；一份第三方对比页（deja-vu 的作者写的，页面上标着 2026-10-28 核对）。星数和功能没有逐个去仓库核对；memmy、memU 以作者 10 月读源码的记录为准。

### 14.1 按怎么采集分四类

| 项目 | 怎么采集 | 常驻服务 | 调模型 | 怎么交给 Agent |
|---|---|---|---|---|
| **读会话文件（和 meme 一样）** | | | | |
| deja-vu | 不采集，直接索引各家已经写在磁盘上的会话，装之前的历史也算 | 没有，一个 Go 单文件 | 不用；向量可选，配了地址才建 | hook 和 MCP |
| memmy | 读会话文件，加 hook 实时写，两条路共用一个解析器 | 有，本机 HTTP 服务（`127.0.0.1:18960`） | 要 | 每轮由 hook 召回并注入；装 Skill 和 hook |
| memU | 定时任务只读地挖宿主的会话日志 | 每个宿主一个旁路程序 | 要，由宿主 Agent 自己提炼 | 在宿主的指令文件里加一段，让 Agent 回答前先去查 |
| agentsview | 读会话文件，归档进本地 SQLite，带文件监听 | 有，带网页界面 | 提炼部分还是实验性的 | MCP：搜过去的决定并引用原消息 |
| **hook 实时采集，加本机服务** | | | | |
| claude-mem | hook 记录每次工具调用；另有会话文件监听器 | 有 | 要，模型写摘要 | 会话开始时注入，加 MCP 搜索 |
| agentmemory | hook 和插件 | 有 | 默认不用，模型和向量可选 | hook 注入，50 多个 MCP 工具 |
| Hindsight | hook：提问前召回，轮末保存 | 有，Docker 服务 | 要 | hook 每轮注入；每个仓库一个记忆库 |
| remem | hook 为主，也能读会话文件补录 | 有后台 worker | 要 | 会话开始时注入，有预算、带出处 |
| **只靠 Agent 主动写** | | | | |
| basic-memory | Agent 通过 MCP 写 Markdown 笔记，人也能改 | 一个同步进程 | 不用 | MCP |
| engram | Agent 调 `mem_save` | 没有，Go 单文件 | 不用 | MCP |
| **改模型接口地址** | | | | |
| 腾讯 TencentDB Agent Memory | 做成模型接口的代理，只改地址 | 自己部署的服务 | 要 | 代理在请求里加内容，不装插件 |

支持 WorkBuddy 的有 memmy、memU 和腾讯这一个。landscape.md 第 2 节还列了 Mem0、Supermemory、ECC、Honcho、ByteRover、Letta Code、EverOS 等，这里不重复。

### 14.2 和 meme 最像的四个

- **deja-vu**：读文件、不起服务、不调模型，这三点和 meme 第一版一样，覆盖 48 家 Agent。但它只做"索引原文再搜"，不提炼事实和经验。
- **memmy**：读取层和 meme 几乎一样，记忆层也已经做出来了（轨迹、经验、场域认知、技能四层）。但它重：要常驻服务、要装 hook、每轮召回、还要模型再过滤一遍。细节见 handoff.md 第 8 节。
- **memU**：同样读会话文件再提炼。但提炼交给宿主 Agent 自己做，还要往宿主的指令文件里加一段。
- **remem**：理念最接近本稿的"可审计"：注入带出处和预算，`remem why` 解释一条记忆为什么被注入，有审核队列，改动要带理由。但它靠 hook 采集，只支持 Claude Code 和 Codex，项目很小（33 星）。

**meme 的位置**：读会话文件、不起常驻服务、提炼成带原话出处的记忆、只写自己的目录、WSL 和 Windows 共用一份。这个组合没看到一样的。它落在两类的交叉点上：读文件的那几个都不提炼，提炼的那几个都要常驻服务或 hook。

### 14.3 别人有、本稿没有的

- **向量或混合检索**：几乎每家都有，多数自带一个本地小模型。本稿定了先不做（13.1 第 14 条）。
- **实时**：hook 那一类每轮都采、每轮都召回。meme 要等会话静下来，每个会话只给一次。
- **看记忆的界面**：agentmemory、claude-mem、agentsview 都有网页。meme 只有命令行和 Markdown 文件。
- **团队共享和跨机器同步**：Hindsight、engram 有。meme 只管本机。
- **接入数量**：Hindsight 60 多家，deja-vu 48 家，agentsview 50 多家。meme 能读 4 家的会话，其余靠 MCP。
