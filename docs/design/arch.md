## 1. 设计原则

1. **如实。** 第一版只做忠实的转化：对话、工具调用和结果原样保留，只遮掉密钥。总结、提炼都留给第二版。
2. **纯代码。** 第一版不调用 LLM，没有 hook，没有常驻服务，也没有后台定时任务。所有工作都在用户运行 meme 命令时完成。
3. **适配层要薄。** 第一版对每个 Agent 只依赖两件事（原来还有"能装一个 skill"，2026-10-10 D17 去掉）：
   - 能读它的会话文件；
   - 能用一条消息启动它。

   2026-10-12 补：每家 Agent 的知识都只放在它的适配器里，其余代码不按 Agent 分支；Agent 升级时怎么少维护，见 6.1 节。
4. **本地优先，原会话为真源。** 会话镜像跟着原会话走；镜像和会话列表都在一个 SQLite 文件里，坏了、删了都能从原会话重建。
5. **出错就放行。** meme 出错，Agent 照常工作。
6. **不登录、不联网、不收集数据、不动用户文件。**
7. **Windows 和 WSL 是一等公民。**

## 2. 整体结构

```
  Claude Code（WSL 和 Windows）          Codex             （第二级：其他 Agent，按需，6.1 节）
  在 Agent 里：! meme continue           终端里：meme continue（2026-10-10 起不装 skill）
        │  运行 meme                        │  运行 meme
        ▼                                   ▼
┌──────────────────────────── meme 命令行程序 ────────────────────────────┐
│ 适配层：找到各家的会话文件 · 交给 trajectory 读取 · 用一条消息启动各家 Agent  │
├──────────────────────────── 基础层（第一版，纯代码）──────────────────────┤
│ 每条命令先做：增量导入 → 写镜像 → 同步删除                                  │
│ meme ls / show（列出、查看） · meme continue（接力） · meme search · forget │
├──────────────────────────── 记忆层（第二版，用 LLM）──────────────────────┤
│ hook · 会话卡 · 提炼 → 写入经验库 → 评估 → 编译 → 三层注入（见 memory.md）   │
└─────────────────────────────────────────────────────────────────────────┘
        │
   ~/.meme/ 数据目录：镜像、会话列表（第二版加会话卡、经验库）
```

**用户实际装的东西**（2026-10-10 起，第一版只装程序，不装 skill，见 D17）：
1. **meme 命令行程序**：所有逻辑都在这里。TypeScript + Bun 打包的单文件为主、npm 为辅（D5，2026-10-08 定，见第 7 节）。
2. ~~**各 Agent 的 skill**~~（第一版不装）：一份说明，告诉 Agent 用户说"/meme"或"接着上次……做"时该运行什么命令、需要细节时怎么用 `meme search`。由 `meme install` 放到各家的 skill 目录。

**安装方式：在终端运行一条命令，一次接上本机所有 Agent**（D13）。用户先把 meme 装到系统上，再由 `meme install` 发现本机的 Agent、导入全部会话；~~放好 skill~~（D17：不装 skill，`~/.meme` 以外什么都不写）（见 [release.md](../research/tech/release.md) 第 4 节）。第一版不做 Agent 插件。

**没有 hook，没有后台任务，没有常驻服务。**

## 4. 工作流程（第一版）

### 4.1 每条命令的第一步：增量导入

```
找到各家的会话文件 ─→ 只读新增或变化的部分 ─→ 脱敏、转换 ─→ 写镜像和会话列表 ─→ 同步删除
```

- **增量**：只比对每个会话文件的大小和修改时间，没变的不重新读；变了就整个文件重新转换，但只写有变化的记录。写到一半的最后一行先不读。
- **首次安装**：导入全部历史（实测约 2 秒）。
- **读哪些会话：在哪装就在哪用。**（2026-10-10 改：装在 Windows 也读正在运行的 WSL 发行版里的会话，通过 `\\wsl.localhost`，见 plan.md 第 ⑤ 步。）装在 Windows，读 Windows 上的会话；装在 WSL，读 WSL 的会话，外加通过 `/mnt/c` 读到的 Windows 会话；装在 Mac 或 Linux，读本机的会话。
- **项目怎么认：和 Claude Code 一致。** 在 git 仓库里用仓库根目录，否则用启动目录；不用 git 远程地址。在 WSL 里读到的 Windows 会话，路径从 `C:\...` 换成挂载路径（默认 `/mnt/c/...`，2026-10-12 起按 /etc/wsl.conf 读挂载位置）；Windows 上读到的 WSL 会话，通过 `\\wsl.localhost` 找，项目写成 WSL 里的路径。worktree 在列表里归到主仓库；判断"在不在原来的位置"时按那套文件自己的根目录（6.3 节）。
- **统一格式分两层**：里层是原样的 trajectory 记录（关掉截断），外层是 meme 补的信息；子代理文件和大输出不复制，只记路径（见 [sessions.md](../research/tech/sessions.md) 第 5 节）。原记录 ID 直接用 trajectory `normalizeToCanonical` 给出的 `stable_source_record_id`：Claude Code 的就是原来的 `uuid`（2026-10-08 实测）。外层的"是否注入"要认全：除了 `isMeta`，还有 `<system-reminder>`、`<task-notification>`、Codex 的 AGENTS.md 和环境信息等（见 [list.md](../research/tech/list.md) 第 5 节）。
- **续接复制的历史**：Claude Code 续接时会把旧会话整个复制进新文件。镜像仍然一个会话一份，标出复制来的记录；列表和检索按会话链合并显示（第 3 步）。
- **脱敏**：写入前只遮格式明确的密钥，遮成 `[REDACTED:类型]`；不做熵检测。
- **同步删除**：按会话 ID 比对，原会话已经不在的，删除它的镜像；数据库开着 `secure_delete`，删除时原文会被覆盖，保证删干净。
  - 来源目录整个读不到时（比如 `/mnt/c` 没挂上），一条都不删；单个文件读不了时，保留旧镜像。
  - Codex 回退后，同一个会话会有两个文件（文件名里带两个 UUID），按会话 ID 归到一起；Codex 分叉出来的会话和子代理的会话也会重放上级的历史，照 D15 标记。（2026-10-10 第 ③ 步实测：分叉和回退按新文件 `session_meta.history_base` 拼，新文件不重放上级历史，见 plan.md §4.5。）这两条来自 cc-switch 的更新日志，待实测（见 [storage.md](../research/tech/storage.md) 第 4 节）。
  - Codex 归档（移到 `archived_sessions/`）、以后可能把旧文件压缩成 `.zst`（代码已有，默认未开启），都只是换了位置或名字，不算删除。
- **在 Codex 沙箱里**：`~/.meme` 只能读不能写。这时跳过写入，需要的会话现场从原文件读取；镜像等下次在沙箱外运行时再更新。

### 4.2 接力

**接力内容怎么来**（两种入口共用）：
1. 找到要接的会话：用户指定，或者取同一项目里最近的会话。
2. 从统一格式的会话里**直接提取**，不做总结（2026-10-12 第 ⑥ 步定稿，详见 [handoff.md](../research/market/handoff.md) 7.3 节），从上到下：
   - 开头说明（历史不是新指令、以仓库为准、步骤已做过、先总结等确认、带了什么和没带什么、怎么查原文）；
   - 接力链：上游会话里用户说的话；
   - 来源 Agent 最后一次能读的压缩摘要；
   - 用户的每一条消息，较早的每条附一行 `↳`（AI 做了什么）；
   - 最后 2 轮的每一步；
   - 改过哪些文件、最近的命令、最后一次验证（测试、构建、lint）；
   - 离开之后仓库的变化：不单独计算。开头说明里提醒接手的 Agent：以仓库现状为准，开工前先看 `git log` 和 `git status`（见 [relay.md](../research/tech/relay.md) 第 3 节）。
3. ~~超出长度预算时，保留开头和结尾，中间注明"用 `meme search` 查"~~。2026-10-12 改：长度按接收的那家 Agent 的命令输出上限定（6.1 节第 3 条）；超了按 6 步顺序删，删完把空间还给 `↳` 行；删了什么写在开头。
4. "重新做"模式只带用户的要求和仓库现状，不带上一个 Agent 的做法。
5. ~~接力内容写成一个文件~~：不生成接力文件，每次现场算好直接输出（D18，2026-10-10）。

**入口一：在新会话里拉取**（2026-10-10 改为由用户用命令选，不靠 skill，见 D17）
1. 在 Claude Code 或 Codex 里输入 `! meme continue`，看到带编号的列表（不经过模型）。
2. 输入 `! meme continue <编号>`（或 `last`、`codex`、标题里的词），接力内容直接进入对话。~~太长时 meme 只输出一行 `@接力文件`~~（D18：没有接力文件，内容控制在接收方能完整收下的长度内）。Claude Code 会自动交给模型；Codex 里再说一句"继续"。
3. Agent 读完接着做；需要细节时运行 `meme search`。

**入口二：在终端推送**
1. 用户执行 `meme continue`（选会话、选 Agent），或者 `meme continue <会话> --in codex`。
2. ~~meme 生成接力文件，再用一条很短的第一条消息启动目标 Agent~~（D18 改）：meme 在会话**开始的目录**启动目标 Agent，第一条消息很短，让它自己运行 `meme continue <id>`，这样仍然避开命令行参数的长度限制。目录不在就报错，并说明怎么在别处拉取（D20）。WSL 的会话从 Windows 推送时，在 WSL 里启动。
3. 目标 Agent 由用户自己安装的程序启动（`claude`、`codex`），meme 不经手任何凭证。

### 4.3 其他命令

- **`meme ls` / `meme show`**：先增量导入，再从会话列表里列出、从镜像里读出。只在终端输出。`meme ls` 照 Claude Code `/resume` 的样子，不显示"最后停在哪"（见 [list.md](../research/tech/list.md) 第 4 节）。每个会话标出来源（Agent、环境），默认放在一起，可以按环境或 Agent 切换、筛选，来源用带颜色的短标签显示。`meme show` 默认每一轮折成一行，想深入时再展开某一轮（见 [list.md](../research/tech/list.md) 第 6 节）。
- **`meme search`**：只读，在沙箱里也能用。不建索引，每次逐条比对；用法照 rg；结果按会话分组，每处标出第几轮，后面接 `meme show <会话> <轮次>`（见 [list.md](../research/tech/list.md) 第 8 节）。
- **`meme forget`**：经用户确认后，删除原会话和镜像。**不删开着的会话**（2026-10-12，第 ⑧.3、⑧.4 步，起因是真机测试 B5 删掉了正在运行的开发窗口）：Claude Code 读它登记开着的会话的文件（`~/.claude/sessions/<进程号>.json`）并核对进程还在；Codex 看它的写入锁；两样都查不到、而最近 5 分钟写过的，也直接拒绝，`--yes` 也一样。

## 5. 数据与存储

### 5.1 数据目录

```
~/.meme/
├── ~~config.toml~~          第一版没有配置文件（plan.md §4.3）
├── meme.sqlite              会话镜像（统一格式，已脱敏，不压缩）、会话列表、每个会话文件的大小和修改时间、读不了的文件和不认识的记录类型（2026-10-12）；
│                            与原会话严格同步，可以从原会话重建
├── ~~handoffs/~~            不再使用：第一版不生成接力文件（D18）
├── logs/                    运行日志
│
├── cards/                   ← 第二版：会话卡
├── store/                   ← 第二版：经验库（git 仓库，唯一真源）
├── packs/                   ← 第二版：编译好的注入内容
├── spool/、tasks/           ← 第二版：hook 的事件记录、任务状态卡
└── run/                     ← 第二版：后台调用模型时的空工作目录，防止记录到自己
```

**原则**
- **镜像是原会话的"同步件"，不是备份**：原会话在，它就在；原会话没了，它就删。
- **第二版的经验库是唯一需要长期保存的东西**：原会话被清理后，经验保留，只把证据标为"原会话已不存在"；只有用户执行 `meme forget` 时才级联删除（见 [memory.md](memory.md)）。
- **原文只放在镜像里，不进 git**：删除时才能真正删干净。

### 5.2 主要数据对象

| 对象 | 是什么 | 存在哪 | 层 |
|---|---|---|---|
| 会话镜像 | 一个会话的统一格式副本 | `meme.sqlite` | 基础 |
| 会话列表 | 每个会话一行，存 8 项：会话 ID、来源（Agent、环境）、项目、标题、分支、开始和最后时间、原文件、续接到哪（见 [format.md](format.md)）；第 ③ 步加了分叉自哪个会话、从第几条起，第 ⑧ 步加了启动目录 | `meme.sqlite` | 基础 |
| 接力内容 | 交给接手 Agent 的内容，每次现场生成，不存文件（D18） | 不落盘 | 基础 |
| 会话卡、经验、注入记录 | 见 [memory.md](memory.md) | `cards/`、`store/`、`meme.sqlite` | 记忆 |

### 6.1 Agent 升级时怎么少维护（2026-10-12 作者定）

**担心的问题**：meme 读的是各家 Agent 的私有格式，没有公开约定，各家又升级得很快。如果每出一版都要跟着改，代码会越来越复杂。

**实际情况：核心稳，外围常变**
- trajectory 的 Claude Code 适配器 7-28 以后、Codex 适配器 8-19 以后都没改过。这期间两家发了很多版，它照样能读，说明核心很稳：用户的话、AI 的话、工具调用和结果、时间。
- 常变的是外围：压缩怎么记、本地命令、各种元数据、历史存在哪（Codex 的分页历史）。
  - 例：Claude Code 记"压缩时保留的原文"的写法，10-10 到 10-12 之间从逐条列出（`preservedMessages`）换成了只给头尾（`preservedSegment`）。meme 不依赖这个字段，一行没改，照样认出了压缩。
- 所以 meme 的维护量，主要来自它选择去读的那些外围内容。

**目标**：维护只在一个地方做；出了问题才做；晚一点做也不影响用。

**六条做法**
1. **核心只读最稳的几样，外围当加分项。**
   - `ls`、`show`、`search`、交接都要求只靠核心记录就能用。
   - 压缩摘要、本地命令、注入原因这些外围内容，读不到时结果差一点，但不能出错。
   - 新功能尽量用不分 Agent 的规则。例：交接里的"最终回复"定成"这一轮最后一次工具调用之后 AI 说的话"，不依赖 Codex 的 `final_answer` 标记。
2. **认不出就降级，不报错，也不悄悄丢。**
   - 不认识的记录，`show` 在会话开头提示条数和类型。（第 ⑦ 步实现：原来想在原位显示一行，但这些记录 trajectory 不输出、镜像里没有，没有原位可显示。）
   - 整个文件读不了时，`ls` 里照样列出，标上 "can't read"，底部提示去看 `meme status`；`show`、`continue` 给一句说明。
     - 第 ⑦ 步实测：trajectory 很宽容，格式不对的记录只是丢掉，几乎不报错。真会整个读不了的是文件层面的问题（压缩文件坏了、没有读权限），这时连目录和版本都读不到，只有会话 ID 和时间：开始时间取自文件名，最后时间取自文件的修改时间。
   - 先读成过、后来读不了：用旧镜像，标 "can't read after <时间>"，`show` 和交接内容里都写明是那个时间的内容；修好以后标记自动消失。
   - 这样 Agent 升级以后，meme 只会变差一点，不会坏掉，维护就不用着急。
3. **每家 Agent 的知识只放在它的适配器里**（"Agent 档案"）。档案里写：
   - 名字、标签、颜色；
   - 怎么认出"正在这家 Agent 里运行"；
   - 当前会话 ID 在哪个环境变量里；
   - 命令输出的上限和单位（[handoff.md](../research/market/handoff.md) 7.3 节末尾）；
   - 压缩行为（handoff.md 7.8 节第 3 点）；
   - 工具结果的固定格式（比如 Codex 输出前面那几行头）；
   - 怎么启动、怎么删除。

   其余代码只看统一格式和档案，不出现"如果是 Codex"这样的判断。维护或新加一家，就是改一个文件、加一个测试样本。

   **命令输出上限怎么用**（10-12 定，细节见 [handoff.md](../research/market/handoff.md) 7.3 节"为什么分三样算长度"）：
   - 交接的结构和删减顺序所有 Agent 都一样，只有"删到多大"按接收的那家定；
   - 认得出是哪家就按那家的上限，认不出就取所有档案里最紧的；
   - 公共上限只有 meme 自己的 1.5 万 token，2.5 万字符挪进 Claude Code 的档案（2026-10-12 第 ⑧.3 步改成 2.7 万字节：Claude Code 把超过约 3 万字节的输出存成文件）；
   - 加一家 Agent 时实测一次它的上限，写进档案（单位：字符、字节，以后可能有行数），留约 10% 余量。
   - **统一定法**（2026-10-12 作者定）：每家的上限 = 实测的命令输出上限 × 90%，用那家自己的单位；`!` 和工具调用不同时取小的；截断、只留结尾、存成文件都算"上限"。现在 Claude Code 2.7 万字节、Codex 3.6 万字节，以后的 Pi 是 4.5 万字节加 1,800 行（handoff.md 7.3 节）。

   **第 ⑦ 步实现**（`src/adapters/<agent>.profile.ts`，登记在 `profiles.ts`）：
   - 档案的项比上面多，分九类：
     - 显示和命名（含 `--agent`、`--in` 的别名）；
     - 启动和安装位置（家目录和改它的环境变量、归档目录、项目说明文件名）；
     - 运行环境（两家嵌套时谁优先）；
     - 交接（输出上限、`!` 的输出会不会自己发给模型、推送的第一条消息、用法说明）；
     - 删除（会不会拒绝删有分叉的上级会话）；
     - 压缩行为；
     - 记录里的文字格式（注入、打断、命令输出、退出码、失败的写法等）；
     - 工具调用的含义（哪个是 shell 命令、改了哪些文件）；
     - 认识的记录类型清单。
   - **第 ⑨ 步补**（2026-10-13）：Claude Code 档案里 `attachment` 改成"读"：用户在 Agent 干活时插进去的话（`queued_command`，来源是人的）算用户的话，第二层报警也盯着它；Codex 档案加了中断的格式（`<turn_aborted>`）、网页工具的名单（交接里标 external content 用）、`session_index.jsonl` 的状态（改名以后马上看得到）。
   - 档案和适配器是两个文件：适配器要引用模型层，模型层又要读档案，放一个文件会循环引用。所以"维护一家"实际是改那一家的两个文件。
   - 适配器以外的 `src/` 里不再点名任何一家。还剩三类不算按 Agent 分支的：
     - 统一格式里的概念（续接链、分叉、`!` 命令、注入原因、压缩）；
     - 模型层同时套用所有档案的文字格式：一条记录不会说明是哪家写的，前提是两家格式不重叠；
     - meme 自己的旧格式（开发期间的 `@接力文件`）。
4. **让 meme 自己发现格式变了，不主动追每个版本。**
   - 每家适配器列一张"认识的记录类型"清单，故意不读的也列上。
   - 遇到清单外的类型，`meme status` 写明是哪家、哪个版本、哪种类型、几个会话。版本从原文件里读：Claude Code 每行有 `version`，Codex 第一行有 `cli_version`。
   - 不用去读各家的更新说明：报警了、或者用户报问题了再改。用户报问题时附上 `meme status`，版本就在里面。
   - 第 ⑦ 步实现：清单 Claude Code 25 种、Codex 23 种，每种写明读还是故意不读；在作者全部会话上报警 0 条（Claude Code 2.1.274–2.1.296，Codex 0.161–0.162）。trajectory 不读的 `local_shell_call` 故意不列，真出现了就该报警。读真会话的测试（`MEME_REAL_SESSIONS=1`）加了"没有不认识的类型"，Agent 升级以后跑一下就知道。
5. **让上游分担。**
   - meme 自己从原文件补的几处，提交给 trajectory：Codex 的 `compacted` 项、Claude Code 的本地命令、`isMeta`。它合并一处，meme 就删掉自己那一处。
   - 万一它不维护了，就把 meme 用到的部分复制进来自己管：约 1,000 行，Apache-2.0，保留许可证说明。
   - 什么时候复制：Claude Code 或 Codex 改了格式、meme 读不对了，而 trajectory 两周内没修；或者它三个月没有任何提交。
   - 10-12 的情况：trajectory 274 star，Letta 公司维护（两位联合创始人都在提交），Letta Code 自己的 dreaming 功能靠它；最后一次提交是 09-25，最近的提交都在做 Slack 对话。
6. **分级支持，控制数量。**
   - **第一级**：Claude Code、Codex。作者用真会话测，外围功能都做。
   - **第二级**：trajectory 支持的其他 Agent（Gemini CLI、OpenCode、Pi、Copilot CLI、Droid 等十几家）。只保证核心功能，不做外围；欢迎贡献，但要附测试样本。
   - 新加一家要有人要才加。README 写明这个分级。
   - **2026-10-13 作者定**：第二级里的 **OpenCode、Pi 提前到第一版**（见 PRD 第 2 节）。当天讨论过第五家：Gemini CLI（Google 已对个人用户停止服务）、DeepSeek Harness（更新太快）、Qwen Code（用的人太少）都不加；GitHub Copilot CLI 作为第一版发布后加的第一家（trajectory 直接支持）。**OpenCode 支持 1.x（npm 包 `opencode-ai`）**：2026-09 发的 2.0（`@opencode/cli`，命令 `opencode2`）是大重写，后台服务加终端、桌面、网页三种界面，服务端接口全换了，trajectory 照 1.x 写的很可能读不了；10-13 npm 周下载 1.x 约 299 万、2.x 约 20 万，等 2.0 稳定了再评估，读到 2.0 的数据时报 "not supported yet"。
     **第 ⑩ 步实现**（2026-10-13，作者对试跑表的答复，plan.md §6 ⑩）：
     - **Pi 的 `forget` 由 meme 删**：Pi 没有删除命令，照 Claude Code 的做法，提示、确认后由 meme 删会话文件，连同它存在临时目录里的长输出全文。OpenCode 用它自己的 `opencode session delete`，提示里说明 `prompt-history.jsonl` 里敲过的话还在。
     - **开着没有**：这家有进程在跑、工作目录就是会话目录时，按"可能开着"拒绝删除；其余照"最近 5 分钟写过就拒绝"。
     - **交接长度**：两家实测都是留尾部、51,200 字节或 2,000 行，按 90% 定为 46,080 字节、1,800 行，第一次用上"行数"这个单位。超了会先丢交接的开头，所以必须守住。
     - **OpenCode 只读它的库**：所有会话在一个 SQLite 库里；meme 只读不写，OpenCode 关着时用 SQLite 的 immutable 方式打开，因为普通的只读打开也会在它的目录里新建 -wal、-shm 两个文件。Windows 上读 WSL 里的库时，复制一份留着，库变了才重新复制。会话 id 去掉 `ses_` 前缀，短 id 和别家一样好敲。trajectory 能读，但要先把库里的数据拼成 `opencode export` 的格式。
     - **推送时不带模型参数**，用那家自己配置的默认模型，meme 不替用户选模型。
     - **和 Claude Code、Codex 比，已知的不同**（第 ⑩ 步真机测试后，`m1-10`）：判断开着没有只能按目录猜，同一目录里开着一个，那里的会话就都不让删；直接装在 Windows、macOS 上的这两家连目录都猜不了，只能按"最近 5 分钟写过"；meme 在这两家里不一定知道自己在哪个会话（OpenCode 不告诉外部会话 id，Pi 只在模型自己跑命令时告诉），"不删正在运行 meme 的会话"靠的是按目录拦；直接装在 Windows 上的两家没实测过；Pi 用 `/fork` 分出来的会话当成独立会话，前面的历史在两个会话里各出现一次（Codex 的分叉能标出来）；OpenCode 2.0 不支持。
     两家只做核心功能：列出、查看、搜索；从它交接出去、推送进它里面；在它里面用 `!` 拉取（它支持的话）；`forget` 只在它自己有删除命令时支持，否则提示到 Agent 里删。每家先本机试跑，按档案的项实测：会话存在哪、trajectory 能不能读当前版本（OpenCode 新版存进了 SQLite，trajectory 读的是它的导出格式）、`!` 的输出给不给模型、命令输出上限（按 90% 定交接长度）、怎么带第一条消息启动、怎么删和怎么判断开着、压缩后原文还在不在。放在第 ⑨ 步之后（第 ⑩ 步）。

### 6.2 WSL 和 Windows：装在哪、看到什么（2026-10-12 作者定）

**现在的做法**（D11，第 ⑤ 步以后）：
- 两边对称：WSL 的 meme 读 Windows 的会话，Windows 的 meme 也读 WSL 的会话（只读正在运行的发行版，停着的不碰）。装一边就能看到全部会话。
- 两边各有各的数据库，因为跨系统访问 SQLite 时文件锁不可靠。

**只有 Windows 时**：
- 标签是 `Claude·Win`、`Codex·Win`；没有平台那一行筛选（镜像里有两种以上平台才出现）；`status` 里没有 WSL。
- 每条命令开头仍会调用一次 `wsl.exe` 问有没有在运行的 WSL。Windows 11 没装 WSL 时 `System32` 里也有一个 `wsl.exe` 空壳，快不快、会不会有提示，**没测过**（作者手边没有 Windows 沙盒）。

**两边都有时装哪边**：在哪边的 Agent 里用 `meme continue`，哪边就要装。
- `! meme continue` 和 Agent 自己运行的 `meme continue`，都在 Agent 所在的系统里跑；
- 从 Windows 推送 WSL 会话时，WSL 里的 Agent 用 WSL 里的 meme 拉取。WSL 里没装时 meme 不启动 Agent，只提示先装。
- 两边都装的代价：两个数据库各镜像两边的会话，磁盘多一份（镜像约为原会话的一半）。在一边 `forget`，另一边下次运行时自动跟着删。

**Windows 读 WSL 要不要留**（10-12 讨论）：**留**。**2026-10-13 作者定：保留**，第二、三轮真机测试都在验收内，总开关只留作后路。
- 理由：
  - 跨环境合并是 meme 少有的独家功能（catchup 就没有，handoff.md 第 8 节）；
  - 已经做完、有测试；
  - 它依赖的是微软的 `wsl.exe` 和 `\\wsl.localhost`，变得慢，在平台层，不随 Agent 增加而变多（6.1 节）。
- 代价：
  - 有 WSL 的 Windows 上，每条命令从 0.12–0.18 秒变成 0.32–0.37 秒。这个不好缓存：记住"在运行"而它其实停了，meme 一读就会把它启动。
  - 只有 Windows 的机器有上面没测过的风险。
  - 在 Windows 上接 WSL 项目，交接内容本来就建议回 WSL 做，所以主要用处是在 PowerShell 里看全、搜全，以及推送到 WSL。
- 留后路：用真机测试来定（第 ⑤ 步的 B1–B6，清单在 plan.md §5；加上只有 Windows 的测试）。问题多就关掉，回到不对称：WSL 读两边，Windows 只读自己。
- **10-12 第二轮真机测试的数**（plan.md §6 ⑤）：读 WSL 让 Windows 上每条命令多花约 150–170 毫秒（`search` 约 310 毫秒，其中一部分是多搜了 WSL 的会话），在"多花 0.3 秒以内"的验收内；WSL 停着时只多约 85 毫秒，也不会把它启动；没有弹窗。偶尔一次 10 秒左右的慢，原因还没查清（怀疑 SQLite 等锁或杀毒软件扫描），第 ⑧.3 步起慢命令会记进日志。

**发布准备里要补的**：
1. **Windows 读 WSL 的总开关**：只在一处判断"Windows 上要不要加 WSL 的来源"。先不对用户公开，只给自己留后路。
2. **没装 WSL 时零代价**：
   - 有 `%ProgramFiles%\WSL\wsl.exe` 就用它（快，约 0.1 秒）；
   - 没有它时，先判断装没装 WSL（比如问一次已安装的发行版，`--list --quiet`，不是 `--running`）；确认"没装"就记下来，一天内不再调用；
   - 只缓存"没装"，不缓存"没在运行"，不然用户启动 WSL 以后最多一天看不到。
3. **只有 Windows 的测试**（没有沙盒时）：
   - 用假的 `wsl.exe` 测：找不到、很慢、报"没装"；很慢到超时（5 秒）时，`status` 要写明 "WSL did not respond"（10-12 开发窗口提议，作者随第 ⑧ 步的消息同意）；
   - 发布准备里本来就要配 GitHub Actions，在它的 Windows 机器上跑一遍 `meme.exe ls`、`status`，量时间。它是 Windows Server，WSL 的情况和家用 Windows 不完全一样，只算近似；
   - 正式发布前请一两个只用 Windows 的人试一下。
4. **安装时提醒另一边**：在 Windows 上 `meme install` 时发现 WSL 里也有 claude 或 codex，就提示"WSL (<发行版>) 里也有 Agent，要在里面用 `! meme continue`，请在 WSL 里也装一份"，并给出安装命令；在 WSL 里装时反过来提示。
5. **只有一种平台时标签不写平台**：和筛选行同一个规则。只用 Windows、以后的 Mac、Linux 用户，`·Win` 这类后缀都是多余的。交接内容开头的 `Source:` 照旧写全。

### 6.3 在哪接着做：只支持在原来那份文件上接（2026-10-12 作者定）

**问题**：接手的 Agent 不一定在会话原来的目录里，比如换了目录、在别的项目里、另一份副本、目录改了名、worktree，以后还有跨机器（SSH、Mac 和 Windows 之间）。作者担心目录不一样、嵌套几层会很复杂。作者平时不会在 Windows 和 WSL 各放一份同一个项目。

**结论：不搞复杂，也不禁止。**
- 只支持"在原来那份文件上接"。其他情况照样给出交接内容，但开头明确告诉 Agent"你不在原来的位置，先问用户"。
- 不禁止的原因：
  - 禁止要做的判断和提醒一样多；
  - 禁止会挡掉正当用法：只是拿来参考、目录搬了家、用户就想在另一份里接着做；
  - 真正危险的只有一种，就是 Agent 不知道自己换了位置，一行提醒就能防住。

**规则**
1. **"在原来的位置"**：Agent 当前所在的那套文件的根目录，和会话那套文件的根目录是同一个。
   - **根目录**：往上找到的第一个 `.git` 所在的目录，不管 `.git` 是文件夹还是 worktree 的那个文件。注意和列表分组不同：列表把 worktree 归到主仓库（plan.md §4.6.9），这里不归，因为 worktree 是另一套文件、另一个分支。
   - 不在 git 仓库里，就比会话开始的目录。（m1-8 实现：当前目录就是那个目录或在它下面，并且不在其中另一个仓库里。）
   - Windows 和 WSL 之间先换算路径，两个方向都换：Windows 会话的 `C:\…` 在 WSL 里换成挂载路径；WSL 会话从 `/mnt/c/…` 开始、在 Windows 的 `C:\…` 里接，按那个发行版自己的 wsl.conf 换成盘符，算同一个位置（m1-8 补）。比较前把符号链接解析成真实路径。
   - 按根目录比，所以在同一个仓库的子目录里接，也算在原来的位置。
2. **不在原来的位置**：交接内容照样给，在 `Source:` 下面第一行加，例如 "Note: This session ran in <目录> (<环境>). You are in <当前目录>, which is not that repository. Ask the user where to work before changing anything. They can also run `meme continue <id>` in a terminal to open an agent in the right place."
   - m1-8 实现：会话不在 git 仓库里，或者原目录已经不在、认不出是仓库（例子 6）时，写 "which is not that directory"。
   - 环境写成 Windows、WSL、macOS、Linux；在 Windows 上读到的 WSL 会话写 "WSL: Ubuntu"。
3. ~~**通过 SSH 运行时**（有 `SSH_CONNECTION`）：一律加"这个会话在另一台机器（<机器名>）上，文件不在这里，先问用户"。~~ **10-12 作者定：不做**，第一版不涉及跨设备。真有人通过 ssh 运行 meme，它比较的是登录目录和会话的仓库，多半对不上，第 2 条的提醒照样会出现，只是说法不够准确。
4. **推送**：
   - 在会话**实际开始的目录**启动，按目标环境换算，不再用项目根目录。这样 worktree、子目录都对了；原来 worktree 的会话会被启动到主仓库，是 bug（m1-8 已修）。
   - 目录不在了，就报错，并说明可以先在想要的目录里打开 Agent，再用 `! meme continue <id>` 拉取（这样就走到第 2 条的提醒）。不加 `--cd` 参数。
   - 补充（2026-10-13 核对代码）："开始的目录"取会话第一条记录里的目录；会话进行中 Agent `cd` 到别处干活，推送仍回到开始的目录。记录里没有目录时，退回到项目目录；两样都没有就报错。推送从不自己挑别的目录：能在原目录启动就启动，不能就不启动并说明原因；只有拉取才可能在别的目录接。
5. **路径要准**（第 1 条的比较靠它）：
   - WSL 挂载 Windows 盘的位置从配置里读（`/etc/wsl.conf` 的 `[automount] root`），不写死 `/mnt/`（m1-8 已改为读配置）；
   - 比较前解析符号链接。

**例子**（Windows 有仓库 `C:\code\shop`，会话 S1 开始在它的子目录 `web`；WSL 有仓库 `/home/jihd/work/meme`（main）和它的 worktree `meme-fix`（fix），另有不相干的仓库 `notes`）：

| # | 情况 | 结果 |
|---|---|---|
| 1 | 在 `meme` 里换一家 Agent 接 meme 的会话 | 照常 |
| 2 | 在 `meme/src` 里接 | 照常（根目录相同） |
| 3 | 在 WSL 的 `/mnt/c/code/shop` 里接 S1；或在 WSL 终端推送 S1 | 照常，多现有的 git 参数提醒；推送在 `/mnt/c/code/shop/web` 启动 |
| 4 | 在 `notes` 里用 `-a` 接了 meme 的会话 | 提醒，Agent 先问用户 |
| 5 | 在 WSL 另外克隆的 `/home/jihd/work/shop` 里接 S1 | 提醒（meme 不分辨是不是克隆，用户回答一句就行）；m1-8 以前的风险是 Agent 去改 `/mnt/c` 那一份，现在开头有提醒 |
| 6 | `meme` 改名成 `meme2` 后接 | 拉取提醒；推送报错并说明在别处怎么拉取 |
| 7 | worktree 的会话 | 推送在 `meme-fix` 启动；在主仓库里拉取会提醒 |
| 8 | 跨设备（另一台电脑、SSH 服务器） | 第一版不支持，请在会话所在的机器上接 |

**不做的**
- 不改交接内容里的路径，原文照搬；路径换算交给 Agent。
- 不判断"是不是同一个仓库的另一份"：不比远程地址，不处理地址写法、fork、搬家。
- 不在硬盘上搜别的克隆，不记两台机器之间目录的对应关系。
- 跨设备接力第一版不做，也不写手动办法（10-12 作者定：怕把用户绕晕）。Windows 和 WSL 算同一台机器。

**以后要做跨机器接力时的分析框架**（10-12 讨论记录，先不实现）
- **每次接力只问三个问题**：
  1. 内容从哪来：哪个 meme 读得到原会话。远程会话只能由那台机器上的 meme 生成。
  2. 新 Agent 在哪干。
  3. 原位置和目标位置是什么关系。

  传输不是问题，交接内容是纯文字。
- **环境之间文件通不通**：
  - 同一环境：通；
  - Windows 和 WSL：通，要换算路径；
  - 不同的 WSL 发行版：各算一个环境；
  - 本机和远程、Mac 和 Windows：不通；
  - 容器：通，但对应关系不固定。
  
  跨机器时路径相同不等于同一份文件。
- **位置关系三类**：
  - A 同一份文件；
  - B 同一个仓库的另一份（克隆、服务器上那份；也可能是搬家或挂载的同一份，分不清）；
  - C 不相干或看不出。
  
  第一版只分"A"和"不是 A"。以后要细分 B，用远程地址认"同一个仓库"（统一 `git@` 和 `https` 写法；几个远程地址有一个相同就算），fork 算 C。
- **还没定的**：
  - B 类时要不要列出原来那份没提交、没 push 的改动（要跑 git）；
  - 跨机器走"对方也装 meme、通过 ssh 调用"，还是把对方的会话文件拷过来自己读；
  - 推送到对方机器时，目录由用户指定。
- **边界情况备查**：
  - Windows 的大小写和 `\\?\`、网络盘（认不出算 C）；
  - Mac 默认不分大小写；
  - 子模块是自己的仓库；
  - 分支不同时交给 Agent 跑 `git status` 自己对。

**已做**（m1-8，2026-10-12）：上面规则 1、2、4、5（第 3 条不做），实现细节见上面各条的"m1-8 实现"。

### 6.4 用户怎么用（2026-10-12 作者定）

目标是用户不被绕晕，所以只讲三件事，内部细节（两份镜像、路径换算）不讲。

1. **范围是一台机器**：Windows 和 WSL 算同一台，互相看得到会话。跨设备（另一台电脑、SSH 服务器）暂不支持，请在会话所在的机器上接。
2. **在哪用 Agent，就在哪装 meme**：Agent 里的 `! meme continue` 用的是 Agent 所在系统里的 meme。只用 Windows 就装 Windows，只用 WSL 就装 WSL（也看得到 Windows 的会话），两边都用就两边都装（在一边删会话，另一边下次运行时自动跟上）。
3. **默认在会话的项目里接**：
   - 在项目里打开新 Agent，运行 `! meme continue`；或者在终端里运行 `meme continue` 选会话，meme 在会话的目录里打开 Agent；
   - 在别的项目里接了会话也行，交接内容开头会提醒，Agent 会先问你在哪做（6.3 节）。

**"我想……"**

| 我想 | 怎么做 |
|---|---|
| 同一个项目换一家 Agent | 在项目里打开新 Agent，`! meme continue` |
| 找不到会话 | `meme ls -a`，或者在列表里按 Ctrl+A |
| 接另一个项目的会话 | 终端里 `meme continue -a` 选它，meme 在那个项目里打开 Agent |
| Windows 上的项目到 WSL 里接 | WSL 终端里 `meme continue` 选它，Agent 在 `/mnt/c/…` 下打开 |
| WSL 里的项目在 Windows 上接 | 建议回 WSL；在 PowerShell 里 `meme continue` 选它，meme 会在 WSL 里打开 Agent（WSL 里要装 meme） |
| 另一台电脑、服务器上的会话 | 暂不支持，到那台机器上接 |

**看到这些提醒怎么办**

| 提醒 | 怎么办 |
|---|---|
| Agent 说"你不在这个会话的仓库里" | 告诉 Agent 在哪做；或者在终端里 `meme continue` 选它，meme 会在对的目录打开 Agent |
| "The repository is inside WSL…" | 回 WSL 接 |
| "meme is not installed in WSL…" | 在 WSL 里也装一份 |
| "WSL (Ubuntu) is not running…" | 列表里 WSL 的会话是上次看到的样子，启动 WSL 后会更新 |
| "run git with `-c core.autocrlf=true …`" | 照做 |

**meme 配合的地方**
- 6.3 节第 2 条的提醒里带上"也可以在终端里运行 `meme continue <id>`，meme 会在对的目录打开 Agent"；
- `meme continue --help` 开头写一句：在会话的项目里接；在终端里运行时，meme 会在会话的目录里打开 Agent；
- README（中英两份）的"接着做一个会话""WSL 和 Windows"两节按本节重写，跨设备只写一句"暂不支持"；
- 安装时提醒另一边也装一份（6.2 节发布准备第 4 项）。

### 6.5 用户怎么报问题（2026-10-12 作者定，放在发布准备里做）

**原则**：meme 不自动上传任何东西，日志只留在用户自己的机器上（PRD 原则"不联网、不收集数据"）。用户遇到问题时，自己运行一条命令生成一份报告，看过没问题再贴进 GitHub issue。报告里不放对话内容。

**现在有的**：
- `meme status`：版本、环境、数据目录、各来源能不能读、读不了的文件、不认识或读不出的记录类型和对应的 Agent 版本；README 已写"报问题时附上它"；
- 日志 `~/.meme/logs/meme.log`：每次导入的统计、每次出错的详情，超过 1MB 换成旧文件；出错时提示 "details in ~/.meme/logs/meme.log"。

**现在的不足**：
1. 日志不能直接贴：里面有用户名（`C:\Users\<用户>`）、项目路径、会话 ID，项目路径可能带公司名或项目名；
2. 打包成单文件后，调用栈写的是 `meme-linux-x64:186:312`，对应不回源代码；
3. 会话本身的问题（显示错、漏内容）往往出在格式上，但会话是私人内容，不能让人贴原文。

**要做的**：
1. **`meme report`**：输出一份可以直接贴的文字：
   - meme 版本、系统和 CPU、环境（WSL、Windows 等）、表结构版本；
   - 各家 Agent 的版本（从每个来源最新的会话文件里读）；
   - `status` 的全部内容；
   - 日志里最近的错误和慢命令记录（10-12 定的"记录慢的命令"）；
   - **自动遮掉**：家目录写成 `~`，用户名遮掉，项目路径换成 `project-1`、`project-2`；
   - 开头写明"这份报告不含对话内容，贴之前请看一遍"。
2. **`meme report --session <id>`**：额外给出这个会话的结构，不给内容：每种记录类型各几行、各有哪些字段名、文件大小、Agent 版本、meme 认出几轮、两层报警各报了什么。格式变了导致的问题大多看结构就能定位；拿到结构后在我们这边写合成样本复现，和"真会话不进 git"一致。还不够时，请用户用新会话造一个最小的复现，不要原文。
3. **出错提示加一句**："To report it: run `meme report` and paste the output into an issue."
4. **让日志更有用**：打包时带上源码映射，让调用栈对应到源代码的行（Bun 打单文件时支持，要实测）；每条错误记下 meme 版本。
5. **GitHub 的 issue 模板**：运行了什么、期望看到什么、实际看到什么、贴 `meme report`；勾一项"我看过报告，里面没有不想公开的内容"。

**收到问题以后**：先看 report 里的版本和报警（Agent 升级导致的问题，报警器多半已经指出是哪家、哪个版本、哪种类型，6.1 节第 4 条）→ 按会话结构写合成样本复现 → 修好、加测试、发新版 → 请用户升级。

| # | 决策 | 为什么 | 代价 |
|---|---|---|---|
| D1 | 本地优先，文件为真源；第二版的经验库用 Markdown + git | 透明、能回滚、能迁移 | 查询靠 SQLite 索引补上 |
| D2 | **第一版不往 Agent 里注入任何东西**，接力内容只在用户要求时交给 Agent。第二版的记忆注入分三层（见 [memory.md](memory.md) 6.3 节） | 第一版不改变 Agent 的行为，不添乱，也不和原生记忆冲突 | 第一版的价值只在统一保存和接力上 |
| D3 | **第一版不调用 LLM** | 和"如实转化"的定位一致；不需要 key、没有费用、不会编造；Anthropic 条款的风险也碰不到 | 接力内容更长、没整理过；会话列表不如 LLM 会话卡好读 |
| D4 | **第一版不用 hook、不用后台任务**，每条命令先增量导入 | 少了 Cursor 误执行、Codex 要手动信任 hook、hook 拖慢启动、Windows 上装 hook 这几个问题 | 会话列表要到运行 meme 时才更新；没有开会话时的提示 |
| D5 | **TypeScript + Bun 单文件为主，npm 为辅**（2026-10-08） | 见第 7 节和 [release.md](../research/tech/release.md) | 单文件约 80 MB；Windows 上刚关闭的 SQLite 文件马上删会报占用，要重试 |
| D6 | 会话镜像统一格式，与原会话严格同步；原文只放在镜像里 | 和官方的保留行为一致；能删干净 | 原会话被清理后，就不能再从它重新学习 |
| D7 | **接力 = 新会话 + 第一条消息 + 按需查原文；不写成原生格式** | 原生格式转换会挤爆上下文、丢信息，各家一升级就容易坏（txcript、Codex 官方导入都有这类问题）；Claude Code 没有官方导入入口 | 推理过程带不过去，只能靠按需查询弥补；以后可以先在有官方注入接口的 Codex（app-server）上试原生方式 |
| D8 | **在新会话里拉取为主，终端推送为辅**（2026-10-10：拉取改为用户用 `!` 命令选，见 D17） | 不需要模型判断；也没有命令行长度限制 | 要用户记得命令 |
| D9 | **不做图形外壳** | 外壳已经饱和；用户不愿意换客户端；外壳的维护成本高 | 少了一个直观的展示面，以后可以做一个轻量面板 |
| D10 | （第二版）生命周期由代码规则决定，LLM 只负责提炼和合并 | 模型的自我评价会越改越偏 | 规则要靠实验来调 |
| **D11** | **在哪装就在哪用**；装在 WSL 的 meme 额外读 Windows 的会话。**2026-10-10 改**：装在 Windows 的也读 WSL 的会话（只读正在运行的发行版），两边对称，装一边就能看到全部（plan.md 第 ⑤ 步） | 和用户使用 CLI 的方式一致；跨系统只读、不跨系统写；数据库必须放在本系统本地（跨系统的 SQLite 锁不可靠，plan.md §4.7） | 两边各装一份时，是两份互不相干的数据（都能从原会话重建，重复无害）；在哪边的 Agent 里用 `meme continue`，哪边就要装 |
| **D12** | **项目按路径认**：git 仓库根目录，否则启动目录；worktree 在列表里归到主仓库（判断"在不在原来的位置"时按那套文件自己的根目录，见 D20） | 和 Claude Code 一致；没用 git 也能用 | 同一仓库克隆两份会被认成两个项目 |
| **D13** | **安装走终端一条命令，一次接上所有 Agent；第一版不做 Agent 插件** | 跨 Agent 是核心，装一次各家都能用；只有一份程序，版本统一；终端里也能用 meme；Codex 插件不能自带程序，走插件会卡住；跨多家 Agent 的同类产品大多这么做 | 要先在终端运行命令；在插件市场里搜不到。第二版要加 hook 时，`meme install` 可能在后台给 Claude Code 装一个插件来放 hook，因为写进 `settings.json` 会改动用户文件，Cursor 也会执行里面的 hook |
| **D14** | **镜像和会话列表都放进一个 SQLite 文件** | 写入、删除在一个事务里完成，几个 meme 同时运行也不会写乱；只有一处要删干净 | 不能直接用 `grep` 看镜像，要用 `meme show`；镜像约为原会话的一半多一点 |
| **D15** | **续接复制来的历史，一个会话存一份，只做标记** | 镜像和原文件一一对应，旧会话被清理后新会话仍完整，同步删除简单 | 本机约 12% 的记录重复存了；列表和检索要按会话链合并 |
| **D16** | **搜索不建索引，每次逐条比对；用法照 rg** | 最准，中文短词、英文片段都能搜到；够快；少一套索引要维护，删除也简单；Agent 熟悉 rg 的用法 | 数据量特别大时会变慢，到时再加索引，用法不变（见 [list.md](../research/tech/list.md) 第 8 节） |
| **D17** | **第一版不装 skill，接力由用户通过命令选择**（2026-10-10，作者选定）：终端里用交互列表；Claude Code 里用 `! meme continue` 看编号、`! meme continue <编号>` 直接把接力内容放进对话；~~推送时第一条消息用 `@接力文件`~~（D18 取代：第一条消息让 Agent 自己运行 `meme continue <id>`）| skill 等于让模型自己判断接哪个，要多绕几轮、多花 token，也不确定；`!` 和 `@文件` 都实测过，不经过模型；少一套要维护的东西 | 不能用一句话触发接力；Codex 也能用 `!`（第 ③ 步实测），但结果不自动交给模型，要再说一句"继续" |
| **D18** | **不生成接力文件**（2026-10-10，作者定）：接力内容每次要用时现场从会话里算好，直接输出给 Agent，不落盘；去掉 `~/.meme/handoffs/`、7 天清理、`@文件`。终端推送时，新 Agent 的第一条消息让它自己先运行 `meme continue <id>`。内容控制在 2.5 万字符以内，免得 Claude Code 里 `!` 和 Bash 的输出被截断（默认上限 3 万字符）（2026-10-12 改：公共上限 1.5 万 token，各家上限写在档案里，Claude Code 2.5 万字符、Codex 3.6 万字节，认不出时取最紧的，见 6.1 节第 3 条）。另外，Claude Code 里 `!` 的结果会立刻发给 Agent（作者实测），所以只看列表时，meme 在列表最后加一句给 Agent 的话，让它只问用户接哪个，不要自己挑 | 接力内容随时能从原会话重新算出来，存成文件只会越积越多，也多一个要删干净的地方 | 终端推送时，新 Agent 要多调用一次命令 |
| **D19** | **Agent 升级时少维护**（2026-10-12，作者定，见 6.1 节）：核心只读最稳的几样，外围当加分项；认不出就降级；每家 Agent 的知识只放在它的适配器里；meme 自己发现格式变化；让 trajectory 分担，它不维护就复制进来；分级支持 | 各家的私有格式变得快，不能每出一版就追一次；实测核心两个多月没变，常变的是外围 | 第二级 Agent 没有外围功能；报警器要维护一张"认识的记录类型"清单；外围变了以后，到修好之前那部分内容会差一点 |
| **D20** | **只支持在原来那份文件上接**（2026-10-12，作者定，见 6.3 节）：Agent 所在那套文件的根目录和会话的相同才算"在原来的位置"；不是就照样给交接内容，开头提醒先问用户；（10-12 作者定：跨设备暂不支持，不做 SSH 的提醒）推送在会话开始的目录启动，目录不在就报错并说明怎么在别处拉取 | 按目录一一对应（克隆、搬家、嵌套、跨机器）很复杂；禁止要做的判断和提醒一样多，还会挡掉正当用法；真正危险的只有"Agent 不知道自己换了位置" | 另一份副本、改了名的目录、跨机器都要用户回答一句才能接着做；meme 不帮着换算路径 |
