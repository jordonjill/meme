## 0. 目标与原则

**项目目标**：开源，积累影响力和技术。首发在中文社区（LinuxDO）。meme 程序以英文为主（命令输出、代码、README），另附中文 README；本项目的设计文档用中文（2026-10-08）。

**产品原则**

| 原则 | 含义 |
|---|---|
| **不做外壳** | 以命令行的形式嵌进用户已经在用的 Agent（在 Agent 里用 `!` 调用，或在终端里用），不要求用户换客户端。"编码 Agent 版 Cherry"这一层已经饱和：AionUi、LobeHub、Cherry v2、codeg、T3 Code 都在做 |
| **第一版如实、纯代码** | 第一版只做忠实的转化和接力，不调用 LLM，不需要 API key；用 LLM 整理、提炼是第二版记忆层的事 |
| **本地、离线、不登录、不收集数据** | 强制登录和收集使用数据，是同类产品被骂得最多的地方之一 |
| **Windows 和 WSL 是一等公民** | 同类工具大多以 Mac 为主；"支持 WSL"的 issue 有 137 个赞，国内用 Windows 的开发者也多 |
| **不添乱** | 出错时不影响 Agent 照常工作 |

## 1. 背景与问题

1. **会话分散，看不全。** 一个开发者的会话散落在多个 Agent、多个项目、多个环境（比如 WSL 和 Windows）里。Vibe Kanban 停运后，用户最怀念的正是"这么多会话里，哪个在做哪件事""休息回来，我做到哪了"。V2EX 上也有人说："会话分散在不同平台，难以统一检索。"
2. **换 Agent 或开新会话，就要重新解释一遍。** 用户的原话：
   - "When you switch tools, you're the context bridge."
   - "我往往充当一个'无情'的复制粘贴者。"
   - "要从 codex 继续原本的对话……会丢失细节。"
3. **同一个 Agent，换个环境也不通。** 同一台电脑上，Windows 和 WSL 里的 Claude Code 会把同一个项目当成两个项目。
4. **记忆本身的问题**（第二版处理）：一次失败被固化成永久规则、记忆过期、记了不遵守、看不见哪条在起作用（见[近期趋势](../research/market/trends.md)第三节）。

**现有方案的不足**：
- 多 Agent 客户端大多只是套壳，每个 Agent 的会话各管各的。
- 能续接的工具，要么只能在它自己的界面里用（T3 Code、codeg），要么只能单向（Codex 官方导入只支持从 Claude Code 到 Codex），要么做原生格式转换，容易丢信息、一升级就坏（txcript）。
- **还没有一个本地的、以命令行形式嵌进现有 Agent 的、跨 Agent 也跨环境的"统一保存 + 接力"底座**，更没有建在它之上的、可信的记忆层。

## 2. 目标用户

- **主要用户**：使用 Claude Code、Codex、Pi 等编码 Agent 的个人开发者，尤其是经常在多个会话、多个环境、多个 Agent 之间切换的人。首发面向中文社区。
- **作者自测**：作者日常在 WSL 和 Windows 两个环境里用 Claude Code，所以"跨会话、跨环境的接力"每天都能自己测；跨 Agent 的部分，要用 API key 运行 Codex 来测。
- **第一版覆盖的 Agent**：Claude Code、Codex（第一级：作者用真会话测，功能都做）。其他 trajectory 支持的 Agent（Pi、Gemini CLI、OpenCode 等）是第二级：有人要才加，只做核心功能（2026-10-12，[arch.md](arch.md) 6.1 节、D19）。
  - **2026-10-13 作者定：第一版再加三家，OpenCode、Pi、DeepSeek Harness**（备选 Qwen Code），只做核心功能（列出、查看、搜索；从它交接出去、推送进它里面；在它里面用 `!` 拉取，它支持的话；`forget` 只在它自己有删除命令时支持）。依据（10-13 查）：OpenCode 21.3 万 star、npm 周下载约 299 万；Pi 11.5 万 star、约 416 万（npm 包已改名 `@earendil-works/pi-coding-agent`）；DeepSeek Harness 24.8 万 star、约 36 万，国产里用的人最多，trajectory 有一个审过、还没合并的 PR #41 支持它。OpenCode、Pi、DeepSeek Harness 在国内用的人都多。~~Gemini CLI~~ 当天去掉：Google 2026-06-18 起对个人用户停止了 Gemini CLI 的服务，替代品 Antigravity CLI 闭源、格式不公开。DeepSeek Harness 还是 0.2 的候选版，格式可能变得快；试跑时对不上就换成 Qwen Code。在第 ⑨ 步之后做（第 ⑩ 步），先本机试跑确认能读、能接（[arch.md](arch.md) 6.1 节第 6 条）。
  - **2026-10-13 再改：第五家换成 Qwen Code**（作者定），DeepSeek Harness 改为备选。Qwen Code 和 DeepSeek Harness 都不在 trajectory 支持的范围里，要自己写读取的代码；Qwen Code 的会话格式和 Claude Code 很像（`~/.qwen/projects/<目录>/chats/<会话>.jsonl`），产品也更稳定。
  - **2026-10-13 最终定：第一版先做四家，Claude Code、Codex、OpenCode、Pi**（作者定）。第五家都不加：DeepSeek Harness 更新太快、格式老变；Qwen Code 用的人太少（npm 周下载约 6.6 万）；trajectory 支持的里面只有 GitHub Copilot CLI 合适（约 155 万、trajectory 直接支持、出自 GitHub），作为第一版发布后加的第一家。Oh My Pi 和 Pi 格式一样，以后加几乎不费事。
  - 选 Codex 作为第二家的依据：在 AIDev 数据集统计的 Agent 所提 PR 里，Codex 最多（3.55 万个）。
  - 作者没有 Codex 订阅，开发和测试时用 OpenAI API key 加便宜的模型运行 Codex。

## 3. 产品定位与分层路线

**一句话**：meme 把编码 Agent 的会话**统一存下来，换一个 Agent 也能接着做**；以后，学到的经验也带得走。

```
第二版起：记忆层（建在基础层之上，设计见 memory.md）
  用 LLM：会话卡 · 提取 → 归纳 → 注入 → 反馈
  会话镜像是它的原料，接力是它的出口
───────────────────────────────────────────────
第一版：基础层（纯代码，如实）
  读取各家会话 → 转成统一格式存下来 → 列出、检索 → 交给另一个 Agent 接着做
```

**和现有工具的区别**：
- **形态不同**：一个命令行工具，在用户现有的 Agent 里用 `!` 调用；不是又一个客户端。
- **范围不同**：同时覆盖跨 Agent、跨会话、跨环境（WSL 和 Windows）。
- **零配置**：不需要 API key，不需要账号，装完就能用。
- **接力**：
  - 在 Claude Code、Codex 里接着做（在会话原来的项目里），需要细节时能查回原文；
  - 接力效果靠内部测试来改进，不做对外公开的评测数字（作者，2026-10-08）。
- **以后的记忆层**：在可靠的底座上，做可信、可验证的经验（见第 6 节）。

**第二版（记忆层），沿用之前的设计**：
- 每个会话有一页 LLM 写的纪要（会话卡），`meme ls` 更好读；

## 5. 第一版范围

### 5.1 必须做（P0）

- **安装与接入**：
  - **在终端运行一条命令安装**，自动发现本机的 Claude Code、Codex（2026-10-13 起还有 OpenCode、Pi），导入全部会话（`meme install`）；`meme uninstall` 干净卸载；`meme status` 查看状态；
  - `~/.meme` 以外什么都不改（2026-10-10）；
  - ~~给每个 Agent 装一个 skill~~：**第一版不装 skill**（2026-10-10，作者选定）：接力由用户自己选会话，不交给模型判断，更快、更确定、更省 token。**不装 hook，不注册后台定时任务，不做 Agent 插件。**
- **统一保存（会话镜像）**：
  - 读取各 Agent 的会话，转成统一格式，脱敏后在本地存一份（不压缩：实测只省 10%，见 [storage.md](../research/tech/storage.md)）；
  - **如实**：对话内容、工具调用和结果原样保留，只遮掉密钥、密码；推理过程不保证能带过去（跨厂商带不过去，Codex 的还是加密的）；
  - 和原会话**严格同步**：原会话不管是被用户删除，还是被 Agent 自动清理，镜像都跟着删除；保留多久跟随各 Agent 自己的设置；
  - 首次安装时导入全部历史（实测约 2 秒）；之后每次运行 meme 命令时，先增量导入、同步删除。
- **列出与查看**：
  - `meme ls` 列出会话，照 Claude Code `/resume` 的样子：每个会话两行，标题，加上多久以前 · 分支 · 文件大小；默认只列当前项目，Ctrl+A 看全部，打字搜索，空格预览；续接链合成一个。另外每个会话标出来源（Agent · 环境），能按环境、按 Agent 切换。不显示"最后停在哪"。Agent 来运行时直接打印一份列表；来源用带颜色的短标签；选中一个会话打开的是查看（见 [list.md](../research/tech/list.md) 第 4 节）；
  - `meme show` 查看某个会话转换后的内容，只在终端输出：默认每一轮折成一行（你的提问、几步几个命令改了几个文件、AI 最后回复的开头），想深入时再展开某一轮：自己看时用方向键和 Enter，Agent 用 `meme show <会话> <轮次>`；能搜整个会话的全部内容（见 [list.md](../research/tech/list.md) 第 6 节）；
  - **每个会话都标出来源，也就是哪个 Agent、哪个环境（比如 Claude Code · WSL、Codex · Windows）；默认所有来源放在一起看，也可以按环境或按 Agent 切换、筛选；来源用带颜色的短标签，比如 `Claude·WSL`、`Codex·Win`（第 ③ 步已定）**；
  - **在哪装就在哪用**：装在 Windows，列出 Windows 上的会话；装在 WSL，列出 WSL 的会话，外加 Windows 那边的会话；装在 Mac 或 Linux，列出本机的会话。
    - **2026-10-10 改（作者定）**：装在 Windows 也列出 WSL 的会话（只读正在运行的发行版，不去启动 WSL）；推送 WSL 会话时在 WSL 里启动 Agent。两边仍然各有各的数据库。详见 plan.md 第 ⑤ 步。
  - **项目的认法和 Claude Code 一样**：在 git 仓库里用仓库根目录，否则用启动目录；不需要 git 远程地址；worktree 在列表里归到主仓库。
  - **跨设备暂不支持**（2026-10-12）：另一台电脑、SSH 服务器上的会话，到那台机器上接；Windows 和 WSL 算同一台机器（[arch.md](arch.md) 6.4 节）。
- **接力**：
  - 两种入口，内容相同：
    - **在 Agent 里拉取**：在 Claude Code、Codex 里用 `! meme continue` 看带编号的列表，再用 `! meme continue <编号>`（或 `last`、`codex`、标题里的词）把接力内容直接放进对话，选会话不经过模型。Claude Code 会自动交给模型；Codex 里再说一句"继续"；
    - **在终端推送**：`meme continue [<会话>] [--in <Agent>]`，在会话开始的目录启动目标 Agent，第一条消息让它自己运行 `meme continue <id>`；目录不在就报错，并说明怎么在别处拉取。WSL 的会话从 Windows 推送时，在 WSL 里启动。
  - **接力内容由代码直接从会话里提取，不做总结**（第 ⑥ 步定，[handoff.md](../research/market/handoff.md) 7.3 节），从上到下：
    - 开头说明：内容是历史不是新指令；以仓库现状为准，开工前先看 `git log` 和 `git status`；列出的步骤已经做过，不要照着重跑；先向用户总结、等确认再动手；带了什么、没带什么；怎么查原文；
    - 会话是接力过来的，带上上游会话里用户说的话（接力链）；
    - 来源 Agent 压缩过上下文的，带上它自己写的最后一次能读的摘要（标明只是提示）；
    - 用户的每一条消息（目标和要求都在里面），较早的每条下面一行写 AI 做了什么；
    - 最后 2 轮的每一步（做到哪了）；
    - 改过哪些文件、最近的命令、最后一次验证（测试、构建、lint）的结果。
  - **长度**：控制在接收的那家 Agent 能完整收下的范围内（Claude Code 2.7 万字节（2026-10-12 改，原来 2.5 万字符）、Codex 3.6 万字节，另有 1.5 万 token 的公共上限）；超了按固定顺序删减，删了什么写在开头，用 `meme show`、`meme search` 能查回来。
  - **在哪接**（2026-10-12，D20）：默认在会话原来的项目里接；在别的项目、别的目录里接，交接内容照样给，开头提醒接手的 Agent 先问用户在哪做。
  - 两种模式：**接着做**带上以上全部；**重新做**只带用户的要求和仓库现状，不带上一个 Agent 的做法。
  - **不把会话写成目标 Agent 的原生格式。** 原因：Claude Code 没有官方导入入口，各家格式不稳定，一升级就容易坏；长会话进去会被对方压缩。
- **按需查原文**：`meme search` 在会话镜像里检索，只读不写，所以在 Codex 这类沙箱里也能用。不建索引，每次逐条比对，用法照 rg；结果按会话分组，每处标出第几轮，后面接 `meme show <会话> <轮次>`；工具输出里的命中默认只显示个数；默认只搜当前项目，`-a` 搜全部，`--session` 只搜一个会话（见 [list.md](../research/tech/list.md) 第 8 节）。
- **删除**：执行 `meme forget`，删除某个会话的原会话和镜像，执行前需要用户确认。
  - **怎么删**（2026-10-13）：Claude Code、Pi 没有删除命令，由 meme 删会话文件；Codex、OpenCode 调用它们自己的删除命令（`codex delete`、`opencode session delete`）。
  - **不删开着的会话**（2026-10-12 到 10-13，第 ⑧.3、⑧.4、⑨ 步）：Claude Code 看它登记开着的会话并核对进程；Codex 看它的写入锁；标着开着、但这里查不了进程的，不管多久都拒绝，提示到那一边删或先关掉；两样都查不到、而最近 5 分钟写过的，也拒绝；真正删除前再查一次；`--yes` 也一样。
- **参数**（2026-10-13，第 ⑨ 步）：`-a`、`--all` 在所有命令里都表示"所有项目"；`search` 里"也列工具调用里的命中"是 `--tools`；`show` 里"也显示注入的消息和推理"是 `--hidden`（`show --all` 会报错并提示改用 `--hidden`）。
- **Agent 升级的防护**（2026-10-12，D19）：每家 Agent 的知识集中在一份档案里；会话读不了时照样列出并注明；遇到不认识或读不出来的记录类型，`meme status` 报告是哪家哪个版本。

## 6. 第二版：记忆层（概要）

详细设计见 [memory.md](memory.md)。第二版开始调用 LLM、使用 hook。

| 环节 | 已定的设计 |
|---|---|
| 会话卡 | 每个会话一页纪要：目标、结果、过程、问题、决定；和提炼经验在同一遍里生成 |
| 读取 | 以单次会话为单位，读整个会话，先瘦身，太长就分段；附带本次注入过的经验，外加最多 20 条相关经验 |
| 抽取 | 经验分为事实和做法；带"来源"和"适用范围"两种 Agent 标签；正文三段式，有字数上限；证据可以核对；按四类原则决定"不抽取"什么 |
| 写入 | LLM 从新增、更新、取代、忽略四种操作中选一种；计数和状态由代码维护 |
| 注入 | 分三层：常驻层、召回层、按需层；明确的和代码探测到的立即生效，推断出来的要攒够证据才生效 |
| 反馈 | 参考 ACE：对每条注入过的经验判断有用、有害或没遇到，按 Agent 分别计数 |
| 分层 | 分用户级、项目级、任务级三层；用户级采用方案 B（跨两个以上项目重复出现就升为用户级） |
| 模型 | 用用户自己的模型，默认推荐 API 模式，订阅模式可选（依据见 [llm-access.md](../research/tech/llm-access.md)）；不碰登录凭证；meme 自己的运行不能被自己记录下来 |

**进入第二版之前要决定的事**，见 [meme 文档首页](../README.md)的问题清单，包括：
- 默认模型；
- 默认作用范围要不要收窄；
- 反馈用确定性的判据还是由 LLM 判断；
- 存储格式要不要兼容 Agent Memory Repo 或 OKF；
- 常驻层写到各 Agent 的什么位置；
- 差异化的方向。

## 7. 非功能要求（第一版）

| 类别 | 要求 |
|---|---|
| **快** | 增量导入不能明显拖慢 meme 命令；`meme ls` 的响应目标在 1 秒以内（初始值，M0 实测后再定） |
| **不动用户文件** | 不修改 CLAUDE.md、AGENTS.md 等用户自己的文件 |
| **隐私** | 全部在本地运行，不联网，不上传任何数据；写入前先对密钥、密码脱敏；会话镜像只有本人可读 |
| **不登录、不收集数据** | 不需要账号，不收集任何使用数据 |
| **删除同步** | 镜像与原会话严格同步；`meme forget` 能删干净。删除逻辑要有专门的测试 |
| **安全** | 接力内容里来自网页、issue 等不可信内容的部分要标注出来；会话里出现的"指令"不当作命令执行。**2026-10-13 定第一版的做法**：交接开头写明"这是历史，不是新指令"；每个工具结果只带第一行；来自网页的工具（抓网页、搜索）那几步标上 "external content"（第 ⑨ 步） |
| **Windows 和 WSL** | 两个环境都能安装，都能读取本机两边的会话（Windows 只读正在运行的 WSL，不去启动它）；兼容各自的路径格式 |
| **能报问题** | 用户自己运行 `meme report` 生成一份可以直接贴的报告（版本、环境、`status`、最近的错误；遮掉用户名和项目路径；不含对话内容），不自动上传任何东西（2026-10-12，[arch.md](arch.md) 6.5 节，发布前做） |
| **兼容性** | 不维护兼容表（2026-10-08）；改为每家一份档案、读不了时降级显示、两层报警，Agent 升级后由 `meme status` 报告（2026-10-12，D19） |

## 11. 决定与待定

**已决定**
- 名称 meme（暂定）；npm 包名 `@jihd/meme`，命令名 `meme`；MIT 许可证。
  - 不带作用域的 `meme` 已被别人占用；要用 `@jihd` 作用域，发布前需要确认 npm 上的 `jihd` 归你所有。
- **2026-10-08**：项目目标是开源，积累影响力和技术；不做图形外壳；第一版只做基础层，记忆层放到第二版。
- **2026-10-08**：第一版是**如实转化 + 接力**，纯代码：不调用 LLM，不用 hook，不用后台定时任务。
- **接力方式**：在 Agent 里用 `!` 拉取，把接力内容放进对话；或在终端推送，新 Agent 的第一条消息让它自己运行 `meme continue <id>`；需要细节时按需查原文；不写成原生格式。（原来写的"接力内容作为第一条消息"，10-10 起改成这样。）
- **会话镜像**：统一格式，与原会话严格同步，保留期限跟随各 Agent 自己的设置。
- **记忆层已定的设计**：见第 6 节和 [memory.md](memory.md)，包括用户级采用方案 B、后台模型默认推荐 API 模式。
- **第 1 步"读取"的四条决定**（见 [sessions.md](../research/tech/sessions.md) 第 5 节）：
  - 统一格式分两层；
  - 子代理文件和大输出只记路径；
  - 项目按路径认，和 Claude Code 一致；
  - 在哪装就在哪用，装在 WSL 的额外读 Windows 的会话。（2026-10-10 改：两边对称，Windows 也读正在运行的 WSL 发行版的会话。）
- **第 2 步"统一存储"的五条决定**（见 [storage.md](../research/tech/storage.md) 第 3 节）：
  - 镜像和会话列表都放进一个 SQLite 文件，不压缩（全文检索索引在第 3 步取消了）；
  - 续接复制来的历史，一个会话存一份，只做标记；
  - 脱敏只遮格式明确的密钥；
  - 同步删除按会话 ID 认，来源读不到时不删，真删除时保证删干净；
  - 增量导入整个文件重转，只写有变化的记录。
- **`meme search`**（2026-10-08）：不建索引，每次逐条比对，用法照 rg；结果按会话分组，每处标出第几轮，后面接 `meme show <会话> <轮次>`；工具输出里的命中默认只显示个数；默认只搜当前项目，`-a` 搜全部，`--session` 只搜一个会话。
- **`meme ls`**（2026-10-08）：照 Claude Code `/resume` 的样子：每个会话两行，标题，加上多久以前 · 分支 · 文件大小；默认只列当前项目，Ctrl+A 看全部，打字搜索，空格预览；续接链合成一个。另外每个会话标出来源（Agent · 环境），能按环境、按 Agent 切换。不显示"最后停在哪"。Agent 来运行时直接打印一份列表；会话怎么结束的（被打断、没回完）放在预览和接力里。
- **查看会话**（2026-10-08）：接力和查看都做，只在终端输出，第一版不做浏览器页面。`meme show` 默认每一轮折成一行（你的提问、几步几个命令改了几个文件、AI 最后回复的开头），想深入时再展开某一轮：自己看时用方向键和 Enter，Agent 用 `meme show <会话> <轮次>`；能搜整个会话的全部内容。每个会话都标出来源，也就是哪个 Agent、哪个环境（比如 Claude Code · WSL、Codex · Windows）；默认所有来源放在一起看，也可以按环境或按 Agent 切换、筛选；来源用标签或图标显示，具体样式在第 3 步定（已定：带颜色的短标签）。
- **`meme forget` 和名字**（2026-10-08）：`meme forget` 双向删除（同时删原会话和镜像；在 Agent 里删的，镜像也跟着删），删之前讲清风险，输入 `yes` 才删；兼容表先不做；产品名叫 `meme`，组织名和域名待定（见 [release.md](../research/tech/release.md) 第 4 节）。
- **不生成接力文件**（2026-10-10，作者定）：接力内容每次要用时现场从会话里算好，直接输出给 Agent，不落盘；去掉 `~/.meme/handoffs/`、7 天清理、`@文件`。终端推送时，新 Agent 的第一条消息让它自己先运行 `meme continue <id>`。内容控制在 2.5 万字符以内，免得 Claude Code 里 `!` 和 Bash 的输出被截断（默认上限 3 万字符）（2026-10-12 改：长度按接收的那家 Agent 的上限定，见下面"交接内容"一条）。另外，Claude Code 里 `!` 的结果会立刻发给 Agent（作者实测），所以只看列表时，meme 在列表最后加一句给 Agent 的话，让它只问用户接哪个，不要自己挑。
- **第一版不装 skill**（2026-10-10）：接力完全由用户通过命令选择（终端交互列表、Claude Code 里的 `!` 命令加编号），不让模型自己判断接哪个；~~推送时第一条消息用 `@接力文件`~~（被上一条"不生成接力文件"取代：第一条消息让 Agent 自己运行 `meme continue <id>`）。接力内容开头本来就写了 `meme search` / `meme show` 的用法。skill 以后需要时再加（见 [release.md](../research/tech/release.md) 第 4 节）。
- **安装、skill、产品语言**（2026-10-08，skill 部分已被上一条取代）：`meme install` 首次导入全部会话；skill 叫 `meme`，只有一个；用户看得到的产品内容一律用英文（见 [release.md](../research/tech/release.md) 第 4 节）。
