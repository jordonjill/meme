> 版本：v0.2 **已定**（2026-10-08，作者确认）；v0.1 草稿列了 30 多项，精简成现在的"每个会话 8 项 + 每条记录 4 项"
> 2026-10-12 v0.4：第 ⑦ 步加了两张记问题的表（第 3.1 节），Agent 版本只记在这两张表里
> 2026-10-12 v0.3：第 ⑥ 步把每条记录第 3 项从"是 / 否"改成"注入原因"（三种值），并写明 meme 自己补的两种记录
> 依据：第 1 步 [sessions.md](../research/tech/sessions.md) 第 5 节、第 2 步 [storage.md](../research/tech/storage.md) 第 3 节、第 3 步 [list.md](../research/tech/list.md) 第 4、6、8 节
> 范围：表里按 Claude Code 写；Codex 那几项从哪取见第 5 节（10-08 已实测）和 plan.md §4.5。只写存什么、为什么存，不写表结构和代码。

## 1. 原则

1. **两层**：
   - 里层是 trajectory 读出来的原样记录：关掉截断，脱敏以后存进去，不改动；
   - 例外是 meme 从原文**补回**的几种记录（trajectory 不输出，meme 按原文位置插回去）：Claude Code 用户敲的本地命令（`/model`、`/compact` 等，plan.md §4.6.3）；Codex 的压缩，在 `compacted` 项的位置补一条 `system` 记录（2026-10-12）；**Claude Code 里用户在 Agent 干活时插进去的话**（`attachment` 里的 `queued_command`，来源是人的；2.1.296 以前没有来源字段，按内容区分），补成一条用户的话（2026-10-13，第 ⑨ 步）；
   - 外层是 meme 自己补的信息，就是本文列的这些。
2. **只存现在用得到的。** 数据库是从原会话转出来的，删了能重建（D14），全量导入一次约 2 秒。以后要用新信息时，加一项、重新导入一遍就行，所以不为以后预留。
3. **能现算的不存，trajectory 已经有的不存。**
4. **对比**：
   - Claude Code 的 `/resume` 每个会话显示 4 项；
   - cc-switch 每个会话存 9 项、每条消息存 5 项；
   - meme 是 8 + 4。meme 自己独有的只有三样：来源、续接链、复制标记，正好对应它比别人多做的事：跨环境、跨 Agent，以及续接链去重。

## 2. 每个会话：8 项（后来加了 3 项，见表下）

| # | 存什么 | Claude Code 从哪来 | 为什么要存 |
|---|---|---|---|
| 1 | 会话 ID | 文件名（和记录里的 `sessionId` 一样） | 认会话 |
| 2 | 来源：Agent 和环境 | 由哪个适配器、在哪个来源目录里读到的决定 | `ls` 的来源标签（`Claude·WSL`，10-10 由 `CC` 改名），以及按 Agent、按环境筛选 |
| 3 | 项目 | 从会话的启动目录（第一条记录的 `cwd`）往上找 `.git`：找到就用仓库根目录，找不到就用启动目录（D12）。Windows 会话在 WSL 里读时，先把 `C:\` 换成挂载路径（默认 `/mnt/c/`，10-12 起按 /etc/wsl.conf）；WSL 会话在 Windows 上读时，通过 `\\wsl.localhost` 找；worktree 归到主仓库 | `ls`、`search` 默认只看当前项目 |
| 4 | 标题 | 依次取：用户改过的标题（`custom-title`）、Claude Code 自动生成的标题（`ai-title`）、第一条用户消息的开头 | `ls`、`show`、`search` 显示 |
| 5 | 分支 | 最后一条记录的 `gitBranch` | `ls` 第二行、`show` |
| 6 | 开始和最后时间 | 第一条和最后一条记录的时间 | `ls` 的"多久以前"、排序 |
| 7 | 原文件：路径、大小、修改时间 | 读文件时记下。一个会话可能有几个文件（Codex 回退后会多一个） | 增量导入：大小和修改时间都没变才跳过；同步删除 |
| 8 | 续接到哪个会话 | `continued-in` 记录 | 把续接链合成一个 |

后来加的三项（都是实现时发现要用的）：
- **分叉自哪个会话、从第几条起是它自己的**（10-10 第 ③ 步，Codex 的 `history_base`）：分叉出来的会话不再重复显示上级的历史；
- **启动目录**（10-12 第 ⑧ 步）：推送时在这里启动 Agent，判断"在不在原来的位置"也用它（arch.md 6.3 节）。项目由它推出来，但 worktree 和子目录会让两者不同，所以单独存。

另外每个来源目录（比如 WSL 的 `~/.claude/projects`、Windows 的 `/mnt/c/Users/<用户>/.claude/projects`）记一行：上次能不能读到。整个目录读不到时，一条都不删。

## 3. 每条记录：trajectory 原样记录 + 4 项

一条记录就是 trajectory 读出来的一条：你的一句话、AI 的一段回复、一次工具调用或一个工具结果。它本身已经带着角色、内容、时间，工具结果还带着"是否成功"。

| # | 存什么 | Claude Code 从哪来 | 为什么要存 |
|---|---|---|---|
| 1 | 原记录 ID | 原记录的 `uuid`。trajectory 的 `normalizeToCanonical` 直接给出（`stable_source_record_id`，10-08 实测全部对上）；一条原记录拆成几条时，再加上 `component_index` | 第 4 项要靠它判断；以后引用某一条 |
| 2 | 第几轮 | 遇到一条真正的用户消息就加一，系统注入的不算 | `show` 的编号和展开；`search` 结果里的"第几轮" |
| 3 | 注入原因（不是注入的为空） | `harness`：Agent 外壳写的（`isMeta`、整条都是 `<system-reminder>`、`<task-notification>` 等）；`compact_summary`：能读的压缩摘要（Claude Code 的 `isCompactSummary`；Codex `compacted` 项的摘要，和它前面那条文字相同的 AI 消息）；`compaction`：压缩过、摘要读不了（加密），只是一个标记 | trajectory 不区分。`show` 默认隐藏、`search` 不搜、算轮次时跳过；交接时带最后一次能读的压缩摘要。2026-10-12 从"是 / 否"改成三种值（第 ⑥ 步，handoff.md 7.3 节） |
| 4 | 是不是续接复制来的 | 续接链上前一个会话里有同一个原记录 ID | `search` 只算一次；`show` 在续接处加分隔线 |

搜索用的纯文字是从里层记录抽出来的一份缓存（已脱敏），属于程序内部的东西，不算一项。

### 3.1 另外两张表：记下读不了的（2026-10-12，第 ⑦ 步，arch.md 6.1 节）

| 表 | 存什么 | 为什么要存 |
|---|---|---|
| `failures` | 读不了的文件、错误类型和第一行、Agent 版本（读得到的话）、旧镜像是哪个时间的 | `ls` 照样列出并标 "can't read"；`status` 说明哪个文件、什么错误；`show` 和交接写明用的是哪个时间的旧内容 |
| `unknown_types` | 每个会话里有问题的记录类型、行数、Agent 版本；`kind` 区分两种：`unknown`（不认识的类型）、`unread`（认识、该读，却没读出记录，m1-7.1 加；m1-8 起还包括 `compacted`：既没有能读的摘要、也没有加密字段；以及 `start directory`：读不到启动目录，这一项其实是会话信息，status 里写成 "(start directory; 1 session)"） | `status` 报"某家某版本写了 meme 不认识的类型"或"认识的类型有几条没读出来"；`show` 开头提示条数和类型 |

- Agent 版本只记在这两张表里（Claude Code 每行的 `version`、Codex 第一行的 `cli_version`），会话本身不记：报问题时才用得到。
- 不认识的记录 trajectory 不输出，镜像里没有，所以只记条数和类型，不能在原位显示。

## 4. 没有存的，各去哪了

| 去处 | 哪些 |
|---|---|
| **现算** | 压缩摘要是哪家 Agent 写的（就是会话的 Agent）、覆盖到第几轮（2026-10-12）；来源标签；"多久以前"；轮数；会话链（由"续接到哪"推出来）；会话大小（各文件大小加起来）；子代理和大输出放在哪（由文件路径推出来：`<会话ID>/subagents/`、`tool-results/`）；怎么结束的（预览时看最后几条记录）；每一轮的一行摘要；搜索结果前后的一小段；会话是否还在运行（看原文件最后修改时间） |
| **trajectory 已经有** | 工具是否报错（工具结果的"是否成功"）、模型（会话信息里有） |
| **接力时从记录里现找** | 改过的文件、最后一次验证（测试、构建、lint 的命令、退出码、输出结尾） |
| **以后需要时再加** | 离开期间回顾（`away_summary`）；每条记录当时的目录和分支、会话结束时的 git 状态（第一版不计算"离开之后仓库的变化"，只提醒 Agent 自己看，见 [relay.md](../research/tech/relay.md) 第 3 节） |
| **不需要** | Agent 版本（2026-10-12：只在第 3.1 节的两张表里记，会话本身不记）；`harness` 注入消息再细分（skill、命令提示词、提醒……）；压缩摘要是哪个模型写的（两家都不在摘要记录里） |
